# Vivarium

一个格子世界里的生命沙盘——你铺下材质、放下自己编辑基因的生物，然后松手，看它们自己长成没人设计过的样子。

**当前状态：M3 进行中** — 世界网格、材质流动（沙塌 / 水流 / 气浮 / 火蔓延）、多线程调度、
**活着的生物**（细胞占格、代谢、行为网络、进食、繁殖、死亡 → 残骸）、
两个渲染器与窗口前端均已可用。

**细胞现在看得见了**：放大之后能看出圆角带膜、按功能上色、同一条鱼的细胞连成一整块。
而且**身体不再只有三格**——四种手工体型，10 到 14 格，尾巴、背鳍、腹鳍、眼睛都在。

生物会在**水平环面**上移动（从右边出去、从左边回来），种群的代数与基因漂移
已经可以观测（12000 tick 跑出 65 代）。但**还没有真正的选择压力**——
目前的基因漂移是中性的，不是适应。

---

## 这是什么

不是"一个有生命的游戏"，而是一个**会自己长出生命的盒子**。三条参考血统：

| 血统 | 代表作品 | 借什么 |
|---|---|---|
| 上帝沙盒 | WorldBox、The Powder Toy | 画笔式神力、灾害工具 |
| 进化模拟 | LifeEngine、The Bibites | 无设计的自然选择、形态自发演化 |
| 物质物理 | Noita、Evolving-Protozoa、ALIEN | 材质规则表、GRN 形态发生 |

刻意**不含**文明 / 王国 / 历史事件层。

## 世界的形状

**横板侧视剖面，有且只有一个重力方向（向下）。** 默认地貌是**海洋 + 岛屿**——大片水体，
散布几座岛屿，生物默认水生。

```
┌──────────────────────────┐
│  天空（约 30%）           │  ← 光从上往下射入，随深度衰减
├──────────────────────────┤
│  水体（约 36%）           │  ← 生物的主舞台：沙会沉、气会浮
├──────────────────────────┤  ← 水面线
│  基岩 / 沉积层（约 34%）  │
└──────────────────────────┘
             ↓ 重力
```

这个决定一次锁死三件互锁的事，所以它必须先定：

| 被它决定的东西 | 后果 |
|---|---|
| 材质规则 | 液体「下 → 左右」、气体「上 → 左右」、固体不动 |
| 更新顺序与并行 | 「自下而上扫描」+ 棋盘 4 相位（同相位分块互不相邻），都是为重力方向设计的 |
| 进化层难度 | 侧视下重力对所有生物都是负担——所以生物默认生活在水里 |

**为什么不是俯视（WorldBox 式）**：俯视下运动容易演化得多，但落沙层会退化成「涂格子」——
沙不会塌、水只能靠水位字段横向摊平，而且没有光梯度。材质层是这个项目的半个乐趣，不能丢。

**光梯度是侧视白送的机制**：生产者细胞必须待在浅水，而浅水正是掠食者的猎场。
垂直位置于是成为真实的生态位。

生成器在 `crates/core/src/worldgen.rs`（`sea_and_islands`）。

## 材质会动

七种材质（空 / 石 / 沙 / 水 / 火 / 气 / 残骸）各自只有**一张属性表**，
规则引擎只负责"按表执行"——加一种材质不需要动模拟循环的任何一行。

| 材质 | 行为 |
|---|---|
| 沙 / 残骸 | 向下落，斜着滑，**不横向找平** → 自然堆成 45° 休止角 |
| 水 | 向下落，斜着滑，被挡住就横向找平（一次最远探查 8 格） |
| 气 / 火 | 倒过来的液体：向上浮、向两侧扩散 |
| 火 | 12 tick 寿命；按可燃度概率点燃邻居；遇水熄灭 |

让路判定只有一条：**更重的挤开更轻的**。"目标必须是空或流体"保证沙丘能立住；
而**上浮不需要单独的规则**——气体顶不开水，但水能沉进气体里，
气泡上浮的真实机制是"上面的水塌下来"。

### 两个不显眼但必须写对的细节

**液体找平必须紧跟一次下落。** 最直觉的"侧邻空着就走"会让相邻两列水位 2/1
互相甩锅、**永远抖动**。后果不是"看起来有点晃"，而是分块脏标记永远清不空，
整个跳块优化直接失效。判据改成"目的地脚下必须能让开"之后，液面只能停在
"相邻列高度差 ≤ 1"——这正是离散网格上"平"的定义。

**世界之外不是空位。** `World::get` 对越界坐标返回 `Empty`（画笔拖到边缘时不该 panic），
但移动判定不能继承这个宽松。漏掉这条，浮到世界顶端的那层气会认为自己还能上浮，
沿着天花板左右滑动永不停歇。而且它只在真实地貌里显形——
人工搭的测试场景里没有那一层气。

> 这两个 bug 都归到同一类：**世界永远静不下来**。
> 它必须是一条测试契约，不是观感问题——一旦不成立，
> SPEC §2.4 的整个性能前提就没了。

## 世界是环形的（只对生物）

**左右边界首尾相接**：鱼从右边出去、从左边回来。材质层仍然是硬边界——
水不会从左边流出去又从右边流回来，因为材质层的分块并行依赖"两块之间至少隔一整块"
这个几何前提，一旦环绕就得把相位划分整个重做。

这条不是装饰。只给"往右"偏置的手工鱼会全部游到右边界堆成一团，
被领地规则卡住，种群停在 9 条——**表面看是生态平衡，实际是"所有鱼叠在一个角落"**。

环绕之后它们会自己散开，同时也暴露了一个更深的假象：局部遮挡和领地这两道负反馈
都是"位置相关"的，鱼一散开就同时失效，种群从 240 条涨到 **1737 条**。
所以补了第三道、也是唯一一道全局负反馈——**环境容纳量**：
生产者越多，每个分到的光越少。三道叠加，种群才真的稳在两百多条。

## 死掉的会烂掉

一格有机物可能有三种来历，而它们的**腐烂规则、运动方式、能不能吃**都不一样：

| 材质 | 来历 | 运动 | 会烂吗 | 能吃吗 |
|---|---|---|---|---|
| 碎屑 | 世界生成撒下的沉积物 | 粉末，会沉 | **不会** | 会 |
| 尸体 | 细胞死亡 | 粉末，会沉 | **会**（水里 20%/25 tick，空气里 3%） | 会 |
| 藻 | 海底长出来的 | **静止** | 不会 | 会 |

**为什么要拆成三种。** 早先它们全叫「残骸」，靠 `flags`（能量）猜身份：
`flags == 0` 被当成"饿死的尸体，可以烂"。于是**带能量的尸体永远不烂**——
实测残骸占比从 1.7% 一路爬到 3.3% 还在涨。而且"该不该还水"也没法判断，
吃掉天然碎屑时也把水还了回去，水位因此漂了二十格。

一个字段被塞了两种含义（"有多少能量" + "是什么东西"），这就是代价。

**腐烂规则搬到了生命层**，因为它要记账：尸体剩下的能量在腐烂时变成热量，
必须进 `dissipated`。材质层没有账本——它悄悄清掉一格带能量的尸体，
守恒断言就会报"多了 N 点"，而那个报错指向的是生命层，查起来毫无头绪。

顺带一个副产品：尸体和碎屑现在**颜色不同**。这不是装饰——"哪儿死过东西"和
"哪儿是海底沉积"是两种完全不同的信息，而它们的形状、密度、行为几乎一样，
颜色是唯一能区分它们的通道。

**空气里的尸体也会烂，只是慢七倍**（3% vs 20%）。概率给 0 就是一个吸收态：
鱼会游到水面之上的天空里死掉，那层尸体永远不消失——实测 8000 tick 堆了 4.3 万格。

天然碎屑永远稳定，所以没有生物的世界依然能完全静止。

## 藻是悬浮物

光只从上往下射，生产者只能待在浅水——于是"待在哪儿"有个平凡的最优解：
**待在最浅的地方**。行为网络没有需要权衡的东西，选择压力只能筛出"别沉下去"。

所以加了第二种食物：**悬浮在透光层水里的藻**。

| | |
|---|---|
| 长在哪 | **水面以下几格的水里**（不是海底） |
| 多快 | 每 25 tick 撒 30 格（通量是常数，和世界大小无关） |
| 多少能量 | 每格 **120**（必须压过"待在水面晒光"的 +26/tick） |
| 有多少 | 存量上限 700 格，实测在 283~700 之间振荡（被吃、又长回来） |

**位置是被两次失败逼出来的。** 长在海底时鱼**够不着**：海深 184 格，
一趟下潜往返的移动成本约 `13 × 368 ≈ 4800`，而一格藻只有 120 能量——
整片藻席吃下去也回不了本。改成"悬在透光层"之后，藻**是固体**，
3000 格就把水流切成碎块：`活跃块` 掉到 3/64、`移动 0`、全部鱼被顶进空气。

所以现在三个条件同时成立：

- **够得着**（长在透光层）——由生命层决定；
- **不挡路**（`is_solid() == false`，鱼能游进去吃）——材质层；
- **不切断水流**（能被水挤开）——材质层。

### 一个自己的移动规则：`MoveRule::Drifts`

| 规则 | 行为 | 谁在用 |
|---|---|---|
| `Static` | 不动 | 空、石 |
| `Falls` | 往下掉，按休止角堆积 | 沙、碎屑、尸体 |
| `Flows` | 往下、找平 | 水 |
| `Rises` | 往上、扩散 | 气、火 |
| **`Drifts`** | **不自己动，但会被更重的水挤开** | **藻** |

**为什么不给藻一个"上浮"规则。** 那要让它和上面的水换位，而水自己也在往下换位——
两格会永远互相换回来，分块脏标记永远清不空，跳块优化直接失效
（同一个陷阱 `try_spread` 里已经踩过一次）。被动让路没有这个问题：
藻只在"别人要过去"时挪，没人动它就静止。

**密度 3（比水轻）。** 水下沉时会把藻顶开，于是藻会慢慢浮到水面那一层——
这不是 bug，是"悬浮物"的必然结果。而且它只让**水**推：沙子落下来时不能和藻
换位，否则藻会被换到沙子上方那一格，而那一格可能是空气——藻飘到天上就下不来了。

**吃掉藻变回水。** 藻是水里的悬浮物，吃掉藻留下水，正是"把藻从水里滤掉"。
写成空位的话，每吃一格藻就少一格水。

> 前两次尝试都在这一节留下了痕迹：藻先是复用「残骸」（粉末，会掉下去），
> 后来是独立材质但静止（会挡路）。**"食物在哪"和"食物是什么"是同一个问题。**

### 嗅觉：四向射线

新增两路输入 `IN_FOOD_DIR_X` / `IN_FOOD_DIR_Y`（−1..+1）。沿四个方向各射一条 20 格的
射线，撞到固体就断（墙后面闻不到），找到含能量的食物就按 `1/距离` 累加一个方向分量。

射线是 80 格/生物/tick，扫方框是 1681；而且射线天然表达遮挡——一条鱼闻到隔壁岩架
后面的藻是没有道理的，它得绕过去。

> **一条分层教训。** 第一版为了让"闻着味道去觅食"真的发生，把嗅觉权重调到 8.0
> （远距离也能压过巡航偏置）。结果是**负收益**：种群从 52 掉到 37、细胞数从 688 掉到 442。
> 那不是参数没调好，是**在错的层解决问题**——手工基因组的职责是"会游、会吃、会生"
> 这条基线，不是替进化决定"该不该觅食"。权重压回 1.5 之后，只保证通道存在且方向正确，
> 要不要用、用多强，交给突变。

## 生物会活

一格要么是材质，要么属于某个有机体的某个细胞——**不能同时是两者**。
这条互斥规则由一张与材质表并列的占格表执行，材质层只读它（`World::yields_to`）：
细胞格的材质字段永远是 `Empty`，如果材质层只看材质，水会灌进鱼肚子里。

最小的鱼是三格：**移动 + 嘴 + 生产者**。但三格放大之后只是三个圆，
所以另外做了四种手工体型：

| 体型 | 格数 | 长什么样 |
|---|---|---|
| 银鱼 | 10 | 三排：背上腹下是生产者，中间一列移动细胞，前端两个嘴 |
| 叶背鱼 | 14 | 背上驮着一大片生产者，像一片会游的叶子；又重又慢，但晒得到光 |
| 蠕虫 | 12 | 细长分节，身体两侧挂着生产者节段；跑 2 格/tick，最穷的一个 |
| 水母 | 12 | 近似放射对称，嘴在正中间，四面都能吃；跑 2 格/tick，没有眼 |
| 掠食者 | 10 | 前端两枚杀手细胞像一对颚；唯一一种"收入不只来自光"的体型 |

**形状不是画着好看就行。** 生产者的边际收益在浅水里约 +14/tick，一个移动细胞要付 6，
所以一个体型能撑几个移动细胞大致就是「生产者数 × 2.3」。生产者太少会饿死，
太多则变成赚钱机器——繁殖快到瞬间铺满。`body.rs` 里有两条测试守着这个区间。

体型只按「朝右」画一遍，朝左时整个身体沿 x 镜像。**掉头是原地翻面，不是转身**——
二维精灵就该是这样，而且不翻的话，一条朝左游的鱼会把嘴留在尾巴那一侧。

| 细胞 | 干什么 | 每 tick 成本 |
|---|---|---|
| 生产者 | 把光转成能量，是唯一的"环境 → 生物"入口 | 5 |
| 移动 | 提供位移，没有它哪儿也去不了 | 4 |
| 嘴 | 吃邻格残骸 | 2 |
| 装甲 | 加重、不产出，只在小体型上做配重 | 1 |
| 眼 | 扩大感知范围 | 1 |

**活着很贵，而且光不够就活不下去。** 光从顶端射入、随深度线性衰减，
所以生产者必须待在浅水；深水里同样的鱼几十 tick 就饿死。
这条梯度是"生物为什么要浮上来"的全部理由。

**能量账是严格守恒的，并且可以直接断言**：

```
Σ 有机体身上的能量 + Σ 残骸蕴含的能量 + 累计耗散 == 累计注入
```

注入 = 太阳能 + 初始投放；耗散 = 维持成本 + 移动 + 死亡时的零头。
残骸的能量存在材质的 `flags` 里，所以残骸沉降、被水冲走时能量跟着走。
512² 跑 8000 tick、两百多条鱼生生死死，这条式子的差额是 **0**。

**行为是一张小网络**：15 路输入（前方有没有食物/阻挡/同类、四向阻挡、
能量比例、年龄比例、朝向、光照、**食物方向 x/y**）→ tanh 隐藏层 8 → 6 路输出
（左右上下 / 吃 / 繁殖）。
手工鱼的基因组是写死的，只做四件事：往前游、撞墙折返、看到尸体就吃、攒够能量就生。
**M2 到此为止——还没有任何东西在进化。**

### 生物占的那格水是「借」的

出生时身体占住一格水，那格水被**借走**；变成尸体时还欠着（尸体占着同一格）；
尸体腐烂或者被吃掉时还回来。于是「水 + 活细胞 + 残骸」是一个守恒量。

**为什么不把水「挤开」。** 早先的写法是把水推到附近的空位，推不下就顶到这一列
的水面之上（水面上升一格，下一 tick 自己流平）。听着更像物理，但它有一个致命后果：
**被顶上去的水成了下一条鱼出生的落脚点。** 一条鱼贴着水面生孩子，子代的水被顶到
亲代头顶；子代再生一个，新子代就站在刚才那格水上——每代往上爬三四格。

实测 512² 跑 8000 tick：水面从 y=153 被顶到 y=107，四十多条鱼骑在水面上，
既不能动也不能繁殖，整个种群冻死在那里。**被顶高的水位是不可逆的。**

配套还有一条：**生物必须贴着水**。移动和出生两道门都要求"身体四邻里有水或气"。
没有它，子代可以生在空气里，而光照越往上越亮——"往天上搬"永远有奖励、从来没有代价。
判据必须是"贴着水"而不是"自己身上有一格水"，因为**身体格的材质永远是 `Empty`**
（材质层与生命层的互斥约定）。第一版写成后者时，`stranded` 指标报出"全部 145 个
都飘在天上"——一个永远为真的指标比没有指标更糟。

> 这一类 bug 的共同点：**跑 100 tick 完全正常，跑 16000 tick 世界变了样。**
> 所以生态测试必须长跑，而且要断言**水位、残骸占比、飘在天上的个体数**这种硬指标——
> 能量账和生物数在崩坏发生时都是健康的。

## 身体是长出来的

默认的身体是五个手工设计的体型。加 `--morph` 之后，身体由一套**生长规则表**
从根细胞长出来：

```text
rules[代][母细胞类型][极性][生长的方向] = 子细胞类型（或者"不长"）
```

从根细胞开始做**广度优先**生长：每一格依次尝试四个方向（右、下、左、上），
能长就长，直到长满上限。全程没有随机数——同一个基因组必然长出同一个身体，
否则"遗传"就不成立。

**为什么是规则表，不是神经网络。** 真正的 GRN 是一张连续动力学图，
细胞的类型由它落在哪个吸引子上决定。听起来很美，但**改一个权重形状往往不变，
改十个权重形状可能崩掉**——那种基因型→表现型的映射对突变太不友好，
搜索会退化成随机游走。规则表正好相反：一个格子被改掉，形状就变一点点。

**四个维度，每一个都是被具体的形状逼出来的。** 第一版只有 `[代][类型][方向]`，
结果蠕虫表达不出来：它两侧各挂一个生产者，同为第 2 代的移动细胞，
一侧要往下长、一侧不要——同一格规则做不到。加"极性"（这个细胞是从哪个方向
生出来的）之后才通。

**热启动：从手工体型反推。** 从零随机搜索撞不出能活的形状，所以
`Grn::from_plan` 把五个手工体型反推成生长程序，长回来**逐格一致**。
于是"形态发生"和"手工体型"是同一套东西的两种写法，突变从这里出发去改。

**突变按"改几条"算，不按逐槽掷骰。** 规则表 16×7×5×4 = 2240 个槽，
5% 的逐槽概率会一次改掉上百条，身体立刻变成随机团。而且优先改**已经打开的**槽
——随机指的话绝大多数时候指到空槽，真正在用的那十几条永远不动。

| tick | 体型（格） |
|---|---|
| 8000 | **10–14**（四五个形状混杂） |
| 16000 | **10–10** |
| 32000 | **10–10** |

### 形状换到什么

形态发生接上之后暴露出一个问题：**形状其实没用**。细胞类型只影响维持成本、
重量和产出，"这几格摆成什么形状"几乎不参与任何计算——于是体型只是
"细胞数量的多重集"，突变把一格换掉就够了，它没有理由去改**布局**。

所以给两个细胞类型接上真正的功能：

| 细胞 | 换到什么 | 怎么算 |
|---|---|---|
| 移动 | **速度**（每 tick 走几格） | `1 + movers/4`，上限 3 |
| 眼 | **嗅觉半径** | `20 + 4×眼`，上限 32 |

**速度是要付钱的。** 每 tick 的移动成本 = `质量 × (速度+1)/2`：

| 速度 | 每 tick | 每格 |
|---|---|---|
| 1 | `1.00 × 质量` | `1.00 × 质量` |
| 2 | `1.25 × 质量` | `0.63 × 质量` |
| 3 | `1.50 × 质量` | `0.50 × 质量` |

"跑得快更烧钱"在**每 tick** 上成立（tick 制模拟里真正要权衡的就是这个），
而每格成本反而略降——多长移动细胞买的是"同样一份钱跑得更远"。

这一条落地时，蠕虫和水母（都跑 2 格/tick）各补了一格生产者才活下来。
水母补的那一格是**用眼换的**：它因此没有眼，嗅觉退回基础值 20。
**看得远是锦上添花，跑得动才是活着。**

**但结论是负面的，而且这个负面结论有用。** 机制接通了（有测试守着：
4 个移动细胞一 tick 走 2 格；1 只眼闻到 22 格外的食物、0 只眼闻不到），
可**最优体型没动**：

| | 16000 tick | 32000 tick |
|---|---|---|
| 手工体型 | 45 生物 / 614 细胞 / 体型 10–14 | 收敛到 **14** |
| 形态发生 | 41 生物 / 554 细胞 / 体型 10–14 | 收敛到 **14** |

两边都收敛到 14 格（6 个生产者的叶背鱼）。**诊断：新能力被"多长一个生产者"压倒了。**
生产者在光 0.8 下净赚约 +14/tick，而一只眼或两格移动换来的**间接**收益远低于这个数
——因为现在这个生态是**光照受限**的，不是觅食受限的：光就在头顶，不需要找。

所以"让形状有用"只做了一半：**梯度存在，但太浅**。要让形状真的被优化，
得让光本身不够养活一条鱼，把生态从光照受限推到觅食受限。

> **一个过程坑。** 第一版顺手把嗅觉基础半径从 20 写成 12（想着"基础 12 + 眼 4"
> 更整齐），结果所有无眼体型的嗅觉一起被砍，最优体型立刻从 10 格跳到 14 格。
> 那不是"形状有了梯度"，那是**削弱**——而且看起来完全像一次成功的实验。
> **加维度的时候不能顺手改已有的绝对值**，否则结果没法归因。

## 追与逃

两路新输入：**最近的别的生物在哪边**（`IN_ORGANISM_DIR_X/Y`）。在它之前你只能
撞上才知道有别人，于是捕食全靠运气、猎物从不躲——那不是生态，是随机碰撞。

引擎只给通道，**怎么反应是基因的事**：

| 倾向 | 谁用 | 接线 |
|---|---|---|
| `Hunt` | 有杀手细胞的 | 靠近 |
| `Flee` | —— | 远离 |
| `Ignore` | 手工起点里的非捕食者 | 不接 |

**"逃"写好了、测过了，但手工起点不敢用。** 一旦猎物会躲，捕食者在三种尺度下
**全部灭绝**（512² 起步 24 / 120 条、128² 起步 20 条）——因为两者**速度一样**，
追的一方永远追不上。这不是"逃"写错了，是"逃"太有效了：它把捕食变成了需要
**技巧**的事，而手工基因组没有技巧。所以"逃"作为一条通道留给突变。

## 有牙的会咬

杀手细胞每 tick 从**邻格的别的生物**身上咬下一口能量。

**咬不咬不是网络输出。** 没有 `OUT_BITE`，也刻意不加——和"手工基因组不该被硬塞
觅食策略"是同一条：**有没有牙由体型决定**。杀手细胞自己就要付维持成本（3/tick，
和生产者一样贵），养不起就饿死，这已经是足够强的选择压力。

**能量是转移，不是注入。** 猎物少多少，捕食者就多多少（装不下的记进耗散）。
所以守恒断言依然成立，而捕食只改变能量的**分布**——那正是频率依赖选择的物理来源。

**装甲第一次有了用处。** 在此之前它只是"加重、不产出"的配重，纯粹是设计上的减分项。
现在每格装甲挡掉 8 点（一口 30 点）：

| 体型 | 装甲 | 实际挨咬 |
|---|---|---|
| 银鱼 / 蠕虫 | 0 | 30 |
| 水母 | 2 | 14 |
| 叶背鱼 | 3 | 6 |

**软的身体成为猎物**，于是"要不要长装甲"第一次是个真问题。

### 捕食者需要猎物密度

这不是 bug，是生态：

| 世界 | 起步 | 8000 tick | 16000 tick |
|---|---|---|---|
| 512² | 24 条 | 杀手 8 枚 | **0 枚（全灭）** |
| 512² | 120 条 | 杀手 14 枚 | **14 枚（稳定）** |
| 128² | 20 条 | 杀手 6 枚 | **4 枚（振荡）** |

128² 那组 `2 → 6 → 2 → 4` 是一个真实的捕食者—猎物振荡。512² 那组说明：
**猎物太稀时捕食者会先饿死**——自然界也成立（捕食者需要最低猎物密度）。
所以游戏里按 L 一次放 16 条而不是 8 条，让玩家能跨过那道门槛。

> 观测上有个坑：捕食者灭绝之后，**"生物数""细胞数""能量账"三项全都正常**。
> 所以加了 `LifeStats::killers`——它归零就说明少了一整个营养级，
> 而那从别的指标上完全看不出来。

## 界面

骨架用 **egui**，关键控件**自绘**。

**结构照 ALIEN**：左边工具、中间视口、右边检查器、下面控制台。
那三个分区不是随便分的——它们对应"操作 / 观察 / 追溯"三种动作。

**皮肤照 The Powder Toy**：纯黑面板、1px 实线边框、悬停提亮、
**按下整体反色**。没有圆角、没有阴影、没有渐变。世界里的每一格像素
都是有意义的，界面不该有装饰性的柔和边缘。

```
┌──────────────────────────────────────────────────────────────┐
│ ▣ VIVARIUM   tick 28431  ● 运行  1× 5× 50× MAX │ 303fps 1.3ms│
├────┬────────────────────────────────────────┬────────────────┤
│ ✏  │                                        │ 选中 #42       │
│ ▤  │                                        │ ▛▀▀▜ 缩略图    │
│ ⬚  │      世界（wgpu 直接画，                │ 能量 312/3500  │
│ ⚲  │       egui 不参与）                     │ ╱╲╱╲ 走势      │
│ 🔍 │                                        │ ‖‖▁‖‖ 17 路输入 │
│    │                                        │ ▬▬▬▬ 6 路决策   │
│    │                                        │ ▦▦▦ 权重矩阵   │
├────┴────────────────────────────────────────┴────────────────┤
│ 材质 ▉▉▉▉▉▉▉▉   细胞 ▉▉▉▉▉▉▉          笔刷 ▬▬●▬▬  2 格    │
├──────────────────────────────────────────────────────────────┤
│  28431  ··· 投放 24 条                                       │
│  32000  !  捕食者降到 1 枚——猎物密度可能不够                 │
└──────────────────────────────────────────────────────────────┘
```

左栏五个工具：**画笔 / 橡皮 / 填充 / 取样 / 检查**（B / E / F / I / Q）。
调色板下半排的细胞色块是**图例**，点不动——细胞的颜色是一套语言，
界面必须把它写出来，但"往世界里单独放一格细胞"不该做成画笔
（细胞属于某个有机体，单独一格是个没有身体的怪东西）。

### 为什么自绘

egui 默认是圆角、内阴影、悬停渐变的"现代桌面"风格。用它的控件再改
`Visuals` 达不到 TPT 那种机械感：圆角半径、内边距、文字基线散在十几个
字段里，改到最后是在别人的设计里打补丁。

自绘的判据可以写成一句话：

> 默认 = 1px 边框 + 透明底；悬停 = 边框变亮；按下 = 整体反色。

自绘的只是**外观**，交互模型照搬 egui（`Sense::click` / `drag`）——
触摸、键盘焦点、无障碍这些没人想重写。

| 控件 | 位置 |
|---|---|
| `flat_button` | 顶栏的速度档、单步 |
| `icon_button` | 左栏的七个工具（图标是 `Painter` 画的几何形状） |
| `swatch` | 底部材质 / 细胞调色板 |
| `value_slider` | 笔刷大小 |
| `stat_row` / `section` / `sparkline` | 右侧检查器 |

### 三条硬约束

1. **不依赖 wgpu / winit。** 和"`vivarium-render` 不依赖 winit"是同一条。
   分开之后界面能在**没有显卡的机器上**跑布局测试——egui 的 tessellate
   是纯 CPU 的。`crates/ui` 的两条测试就是这么跑的。
2. **不认识模拟。** 输入是 `Snapshot`（只读快照），输出是 `Command`
   （要主循环做的事）。界面里没有 `&mut World`。
3. **不自带配色。** 色块颜色取自 `vivarium_core::palette`——界面上的绿
   必须就是世界里那个绿，否则"点这个会画出什么"要重新学一遍。

### 想看一眼界面

`png` 只是 dev-dependency，不进发布产物，所以截图是个测试：

```bash
cargo test -p vivarium-game --test ui_preview -- --nocapture
# → target/ui-preview.png
```

它同时是一组**像素断言**：五块面板的底色、左栏边界的精确位置、
中央没有被面板盖住、每种材质和细胞的色块都真的画出来了、
检查器里确实有文字。这个模型看不了图，所以"看一眼"换成了这些判据。

### 中文字体

egui 内置字体不含 CJK。不装的话界面上的中文全是方块——那不是"不好看"，
是整个界面不可读。但一个中文字体 10~20 MB，而 `dist/vivarium.exe` 只有
6.8 MB，打进去体积翻三倍。

所以启动时按 `雅黑 → 黑体 → 宋体` 的顺序找系统字体，找不到就在横幅里
明说"中文会显示成方块"。

### 现在能做什么

**改世界**：画笔（圆形笔刷，半径可调）、橡皮、填充（四邻域，封顶 6 万格）、
取样。左键落笔，**右键或中键拖拽平移**，滚轮**以指针为中心**缩放。
笔刷半径有预览圈——多涂三格水和少涂三格在画面上都不明显，只有能量账知道。

工具只有五个：**画、擦、填、吸、看**。矩形和直线被去掉了：它们需要
"按下 → 拖动 → 松开"三段式，而拖拽现在是平移视野，两个功能抢同一个手势
一定有一方误触。

**画笔不涂生物。** 一格要么是材质要么是细胞，硬涂上去会让占格表和材质打架
（那条鱼还占着这格，而格子已经变成石头），症状是"鱼突然不动了"。

**看世界**：速度档、暂停 / 单步、投放、点火、重铺地形、缩放回正。

**看一个个体**（用「检查」工具点它）：身体缩略图、能量 / 上限、年龄、
维持与移动成本、速度、嗅觉、能量走势、细胞构成条，以及——

- **17 路感知**画成一条竖带（哪几路在动一眼可见，悬停看数值）；
- **6 路决策**画成条，外加"本 tick 在做什么"；
- **行为网络的直连权重矩阵**（17 行 × 6 列热力图，绿正红负）。

最后那一条是重点：只给"能量 312、速度 1"回答不了"它为什么这么动"；
给出"光照 0.70 → 上（−3.0）"和"食物 y +0.55 → 下（+1.5）"之后，
"它为什么在这个深度"就变成一道自己能算的题。

## 快速开始

需要 Rust stable 与 MSVC 工具链（Windows）。

```bash
# 图形前端：开窗，看像素画面
cargo run --release -p vivarium-game

# 没有 GPU 或没有显示器时，在终端里跑同一套内核
cargo run -p vivarium-game -- --ascii

# headless 模拟并打印 ASCII 视图
cargo run -p vivarium-sim -- --width 256 --height 256 --ticks 1000 --ascii

# 在最高的岛顶点一把火，每 500 tick 报一次进度
cargo run --release -p vivarium-sim -- --ticks 3000 --ignite 40 --report-every 500

# 在水面附近放 20 条鱼，看它们游、吃、生、死
cargo run --release -p vivarium-sim -- --ticks 3000 --fish 20 --report-every 500

# 指定材质层的并行工人数（默认 0 = 自动）
cargo run --release -p vivarium-sim -- --ticks 1000 --threads 4

# 对照实验：关掉藻，看它到底改变了什么
cargo run --release -p vivarium-sim -- --ticks 16000 --fish 24 --no-algae

# 形态发生：身体由基因组**长出来**，而不是用手工体型表
cargo run --release -p vivarium-sim -- --ticks 16000 --fish 24 --morph

# 查看全部参数
cargo run -p vivarium-sim -- --help

# 测试
cargo test --workspace
```

窗口里的操作：

| 输入 | 作用 |
|---|---|
| **左键** | 落笔（工具决定画 / 擦 / 填 / 吸 / 看） |
| **右键或中键拖拽** | 平移视野 |
| **滚轮** | 以指针为中心缩放 |
| `B` / `E` / `F` / `I` / `Q` | 画笔 / 橡皮 / 填充 / 取样 / 检查 |
| `空格` | 暂停 / 继续 |
| `1` / `2` / `3` / `4` | 速度 1× / 5× / 50× / 最大 |
| 方向键 / `0` | 平移 / 回到全景 |
| `L` / `G` / `R` | 放鱼 / 点火 / 重铺地形 |
| `Esc` | 退出 |

也可以一开始就带着鱼启动：`cargo run --release -p vivarium-game -- --fish 40`。

**想看清细胞，把窗口开小一点再放大。** 512² 的世界塞进 1100 px 的窗口是 2.1 px/格，
一条三格鱼总共 6×2 像素——不是渲染坏了，是采样率不够。两个办法：

```bash
# 让世界变小，同样的窗口就有了 8.6 px/格
cargo run --release -p vivarium-game -- --width 128 --height 128 --fish 20
```

或者直接滚轮放大到十几倍。窗口标题里那个 `px/格` 就是当前密度。

`vivarium-sim` 不依赖任何图形库，可以在没有显示器的机器上跑长测。
它的报告里有四个比 hash 更该盯的数字：**活跃块数**（世界平静后应当掉到 0）、
**材质变化表**（守恒出问题时直接告诉你是哪种材质多了或少了）、
**工人数**（这一跑实际用到了几个线程），以及
**能量账的差额**（只要不是 0，就说明有一条能量通道没走记账点）。

## 打包

每完成一版都打一次包，产物是**双击就能跑的单文件 exe**（不需要装 Rust、不需要装任何运行库）：

```powershell
.\scripts\package.ps1              # → dist\vivarium.exe
.\scripts\package.ps1 -IncludeSim  # 顺带打包 headless 模拟器
```

`dist\VERSION.txt` 记录这一份是哪个 commit 构建的。`dist/` 不入库——
仓库里只有源码和这个脚本。

打包完记得**试运行一次**：编译通过不等于 exe 能跑，wgpu 的适配器初始化
只有在真的开一次窗口之后才知道成不成。

> 中文提交信息在 `VERSION.txt` 里会乱码，除非调 git 之前把
> `[Console]::OutputEncoding` 改成 UTF-8。PowerShell 解码外部程序 stdout 时用的是它，
> 而它在中文 Windows 上默认是 GBK(936)——git 吐出的 UTF-8 字节被按 GBK 解，
> 就成了"璁╃粏鑳炵湅寰楄"。不是 git 的问题，是宿主的问题。

### 想看一眼渲染结果

不用开窗口，直接把离屏渲染导成 PNG：

```bash
cargo test -p vivarium-render --lib -- --ignored --nocapture render_preview_png
# → target/render-preview.png          刚生成的地貌
# → target/render-preview-settled.png  材质层跑完之后的同一张图
# → target/render-preview-life.png     放鱼并跑 300 tick 之后

# 放大看细胞：一个近景、一个全景
cargo test -p vivarium-render --lib -- --ignored --nocapture render_preview_cells
# → target/render-cells-close.png      17 px/格，看得到膜、融合、按功能上色
# → target/render-cells-wide.png       zoom 3，看地貌与鱼群分布
```

像素渲染的 bug（颜色偏了、上下颠倒、留边错位）几乎都是"看一眼就知道、
但很难写好断言"的那一类。三张图能一次覆盖全部像素，而它们的**差异**
就是"材质规则和生命层真的在工作"最直观的证据。

第三张还钉住一件容易写错的事：细胞格的材质字段永远是 `Empty`，
如果脏块检测只看材质，鱼在水里游的时候渲染器会认为什么都没变，画面上一条鱼也没有。

近景那张另外钉住一条：**同一条鱼的细胞必须连成一块，不能有接缝**。
这条在 CPU 侧完全看不出来（键都写对了），只有真的把像素读回来量接缝亮度才发现——
第一版融合逻辑写对了，但明暗用了到格边界的距离，格边界处亮度归零，
身体于是又被切回一颗颗糖。

## 项目结构

```
crates/
  core/    模拟内核：材质、材质流动（含并行调度）、细胞与有机体、生命层调度、
           网格分块、确定性随机、地貌生成、手工体型（`body.rs`）、
           形态发生（`grn.rs`）  ← 零依赖
  render/  Renderer trait + ASCII 渲染器 + wgpu 像素渲染器
           （`shaders/blit.wgsl` 里做 SDF 细胞形状、融合、按功能上色）
  ui/      界面层：主题（`theme.rs`）、自绘控件（`widgets.rs`）、
           五个面板（`panels.rs`）、状态与命令（`state.rs`）
           ← **只有 egui，没有 wgpu / winit**
  app/     主循环、输入、时间控制
bins/
  sim/     headless 模拟器
  game/    图形前端（winit 事件循环 + egui 的 GPU 接线，见 `ui_glue.rs`）
```

地貌生成刻意放在 `core` 而不是各个 bin 里：M0 期间它被复制了三份
（sim / game / 渲染预览测试），三份已经开始漂移。世界形状是**设计决定的载体**，
不该有互相矛盾的实现。

## 四条架构约束

这几条不是风格偏好，是设计决定：

1. **`core` 不依赖任何渲染或窗口库。** 验证进化靠的是"跑几千上万代"，不是"盯着画面看"。
2. **`bins/sim` 刻意不依赖 wgpu / winit / egui。** 一旦它拉进图形依赖，每次编译多等几分钟，长跑调参就废了。
3. **`render` 不依赖 winit。** 它只接受一个已经建好的 `wgpu::Surface`——窗口是应用层的事，画像素不是。这样 headless 渲染不必拖进一整套窗口系统。
4. **`ui` 不依赖 wgpu / winit。** 只有 `egui`。界面的布局、配色、控件逻辑都能在**没有显卡**的机器上测——`crates/ui` 的两条测试正是这么跑的。把三角形提交给 GPU 是 `bins/game` 的事。

另外，`Renderer::render` 只接收 `&World`——"切换渲染器不改变模拟结果"这条验收断言，靠签名在编译期兜底。

## 渲染：脏块增量上传

世界纹理与世界同尺寸（512² 约 1 MiB），但**每帧只重传变过的 64×64 块**。

带宽其实不是瓶颈（1 MiB × 60 FPS = 60 MiB/s，GPU 不在乎）；
真正的成本是 CPU 侧的逐格转换——262144 个格子逐个算、逐字节写入。
分块之后，静止的块连这一步都省了。

这与 SPEC 第 2.4 节一致：落沙层的成本取决于**活跃格子比例**，不是网格大小。

按 `R` 重铺地形时，窗口标题里的"本帧上传"会瞬间跳到满格再掉回 0——
那就是增量逻辑在工作的直接证据。

## 纹理存的是语义，不是颜色

世界纹理是 `R32Uint`，每格一个键：

```
0x8000_0000 | (organism << 8) | cell_type
└─ 是细胞      └ 个体 id        └ 细胞类型
```

**颜色、形状、膜、轮廓光，全在 shader 里从键算出来。** 一开始的写法是 CPU 查调色板、
往纹理里写 RGBA——那意味着"这一格长什么样"在 CPU 侧就定死了，而 CPU 一格只能写一个颜色，
所以一格只能是一个方块。

想要圆角、想要同一条鱼的细胞连成一整块、想要膜在身体内部不出现、想要按功能而不是按个体上色，
这些全是**像素级**判断，只能在 shader 里做，而 shader 需要的是语义，不是颜色。

于是占格表多了一个 `kind: u8`（这一格是嘴还是生产者）——**不多占内存**，
`u32 + u16` 本来就要 padding 到 8 字节，白赚。之所以存在占格表而不是让渲染器去查生命层：
渲染器只拿得到 `&World`，为了知道"这是嘴"而让它持有整个 `LifeSim`，是把两层焊死。

### 融合不是"画粗一点"

同一条鱼的相邻细胞之间不该有缝。做法是**查四邻居**：同 `organism` 的一侧，把边界从格内
推到格外（`±0.5 → ±1.0`）。于是身体内部那几面墙根本不存在——边界是**从邻居关系推出来的**，
不是估出来的，所以身体形状换了会自动跟着变。

这里有一个只有把像素读回来才发现的坑：融合逻辑写对了，但明暗用了"到格边界的距离"，
而那个距离在格边界处正好归零。结果是**刚融合好的身体又被切回一颗颗糖**。
改成按"到格心的距离"算，融合处的亮度由两侧各自贡献，不会掉到零。

基础亮度也因此从 0.5 抬到 0.72：细胞边界处亮度本来就低，基础值再低，
两颗细胞相接的地方会暗到和水几乎同色，看起来像断成两截。

### 按功能上色，不按个体

嘴橙红、生产者绿、移动青蓝、眼黄、杀手紫红、装甲灰蓝、构造器琥珀。
这条是从 ALIEN 借的视觉语言：**看颜色就知道这格在干什么**。

按个体上色看起来更"丰富"，但它把注意力引到"这是谁"，而结构信息在"这是什么"。
一个身体要能看出结构，先得让同一种细胞在视觉上连成一片。

## 相机

`Viewport { center, zoom }`，属于渲染层，**不进世界哈希**——它改变的是"看哪里"，不是"发生了什么"。

滚轮缩放、方向键平移一成视口、`0` 回全景、`+`/`-` 快速缩放。窗口标题实时显示 `px/格`。

这个功能存在的理由只有一个：**512² 塞进 1100 px 的窗口是 2.1 px/格**，
一条三格鱼是 6×2 像素。在加相机之前，"看不到细胞结构"看起来像渲染 bug，
实际是采样率不够——`--width 128 --height 128` 一行就能零成本验证。

> 顺带一个调试陷阱：`ensure_world` 首次建纹理会把相机重置到世界中心。
> 离屏渲染测试里如果先设 viewport 再 `upload()`，重置会**静默覆盖**掉视口，
> 结果看起来像"细胞根本没画出来"——但键、shader、绑定全是对的。
> 修法是先 upload 再设 viewport，并且只在世界尺寸真的变了时才重置。

## 可复现性

所有随机走固定种子的 PCG 发生器（手写、零依赖），禁用系统随机。
契约：**同种子 + 同操作序列 ⇒ 同结果**，网格哈希逐 tick 一致。

```bash
cargo run -p vivarium-sim -- --quiet --seed 42 --ticks 1000 | grep hash
```

材质层每格每 tick 要做的随机决策（往哪边滑、这一格点不点得着）走的是
**位置派生**随机数 `Rng::at(x, y, tick, salt)`，而不是上面那个顺序推进的 RNG。
理由不是性能，是**可验证性**：共享的顺序 RNG 会让"哪些格子先被处理"变成世界状态的一部分，
于是并行化和跳块扫描都成了无法验证的赌博。

换成位置派生之后，"跳块扫描"与"每 tick 全网格扫描"给出**逐格相同**的结果，
这条性质是直接写成测试的（`skipping_static_chunks_matches_a_full_scan`）。
并行也是同一回事：`--threads 1` 与 `--threads 16` 逐 tick 哈希相同
（`thread_count_does_not_change_the_world`）。

但**扫描顺序本身**是这个世界定义的一部分。分块按棋盘相位分组是并行的前提，
而分组必然改变"谁先被处理"——把顺序改掉，同一个种子会长出另一个世界
（物理结果不变，具体排布会变）。所以有一条黄金哈希测试
（`the_scan_order_is_part_of_the_world`）钉住它：以后谁动扫描顺序，它会立刻红。

### M1 实测

| | |
|---|---|
| 512² 满负载（沙雨传送带）1 线程 | **3.44 ms/tick** |
| 512² 满负载 8 线程 | **1.59 ms/tick（2.16x）** |
| 512² 满负载 自动档（落在 8 工人） | **1.65 ms/tick** |
| 512² × 20,000 tick（真实地貌，绝大部分时间静止） | **146 ms**（0.0073 ms/tick） |
| 世界静止所需 | **221 tick**（此后活跃块恒为 0，每 tick 访问 0 格） |
| 测试 | 136 个全绿 · clippy 零警告 |
| 跳块 vs 全扫 | 400 tick 逐 tick 逐格哈希相同 |
| 线程数 vs 结果 | 1 / 2 / 4 / 8 / 16 线程，逐 tick 哈希相同 |

**多线程已经接上了**，而且不是"能跑就算"：分块先拷进私有副本、规则只在副本上跑、
相位之间由主线程顺序写回，所以线程之间没有任何共享的可变状态——
"线程数不影响结果"是构造上成立的，不是靠多跑几次碰运气。

调参用 `--threads N`，默认 0 = 自动（按本机核数与当 tick 活量收敛）。
注意**不是线程越多越快**：建一个线程约 30 µs，所以 `--threads 16` 在这台机器上
反而比 8 慢——自动档就是为了避开这件事。

### M3 实测（手工体型）

| | |
|---|---|
| 512² × 16000 tick，24 条起步 | 种群 37 · 细胞 518（均 14 格）· 最大代数 45 |
| 能量账 | 差额 **0** |

**加大体型不是换个数据表。** 它把一整类只在多格身体上才显形的问题一次全暴露了，
五个真 bug 里有三个是同一件事的不同面孔——**生物会离开水**：

1. **感知探针取在锚点上。** `front()` 返回锚点右侧一格，而三格鱼的身体本来就占住
   那一格——"前方被挡"恒为真，手工鱼其实**一直在往左游**。它看起来正常，只因为
   撞到左墙会反向。十几格的身体把这个错放大到无法忽视。
2. **繁殖是爬进天空的梯子。** 子代位置在亲代 6 格以内，而 `can_place` 对空气放行。
   水面上的鱼可以一路往上生，每代 6 格。
3. **被挤上去的水成了下一代的落脚点。** 见上面「借水」那节。
4. **尸体腐烂成"空"，水回不来。** 海底攒出空气腔，水位被永久顶高。
5. **干残骸永远不烂（吸收态）。** 概率给 0 就是只进不出，天空里那层尸体永不消失。

还有一个不是模拟的：**`cargo test` 并行跑 GPU 测试会 `STATUS_ACCESS_VIOLATION`**。
DX12 的软件适配器上多个 device 并发创建不是线程安全的，现象是"跑三遍崩两遍、
单线程跑全绿、而且不告诉你崩在哪个测试里"。加一把全局互斥锁把 GPU 测试串起来即可。

### 一次失败的实验：把生态推到"觅食受限"

目标：24 的时候光本身就够活，"跑得快 / 看得远"永远不如"多长一个生产者"。
要让形状有东西可优化，得让光**不够**活。做法是 `PRODUCER_YIELD` 24 → 15 +
藻生长率 8% → 40%。**失败了，已回退。** 三个硬障碍：

1. **食物在海底不可达**：48 条鱼 4000 tick 全灭，藻席堆到 800 格没人吃。
   海深 184 格，一趟往返移动成本 ≈ 4800，而一格藻只有 120 能量。
2. **加"饿了往下"也不够**：下潜要 184 tick，启动能量只够撑 125 tick。
3. **改成浮游藻把世界冻住**：藻是静态固体，悬在水里就成了水流的障碍——
   1500 格时 `活跃块` 掉到 3/64，3000 格时整个世界静止（`移动 0`）。

**这不是调参能解决的。** 要让食物"可达又不成障碍"，藻需要自己的移动规则
（随水漂、可被水挤开），那是一次材质层的改动。在那之前宁可"光照受限"但生态健康。

> 一句话：**"食物在哪"和"食物是什么"是同一个问题。** 把食物放在鱼到不了的地方，
> 等于没有食物；把食物做成挡路的东西，等于把海填了。
