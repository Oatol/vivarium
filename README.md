# Vivarium

一个格子世界里的生命沙盘——你铺下材质、放下自己编辑基因的生物，然后松手，看它们自己长成没人设计过的样子。

**当前状态：M3 进行中** — 世界网格、材质流动（沙塌 / 水流 / 气浮 / 火蔓延）、多线程调度、
**活着的生物**（细胞占格、代谢、行为网络、进食、繁殖、死亡 → 残骸）、
两个渲染器与窗口前端均已可用。

**细胞现在看得见了**：放大之后能看出圆角带膜、按功能上色、同一条鱼的细胞连成一整块。
而且**身体不再只有三格**——四种手工体型，10 到 14 格，尾巴、背鳍、腹鳍、眼睛都在。

生物会在**水平环面**上移动（从右边出去、从左边回来），种群的代数与基因漂移
已经可以观测（12000 tick 跑出 65 代）。但**还没有真正的选择压力**——
目前的基因漂移是中性的，不是适应。

**世界现在有光也有热了**：一张 4 像素一格的空气场，太阳逐列射入、被石头挡住、
点光源四向扩散；温度会扩散、会冷却，并且真的会影响生产者的产能。
顶栏有**四个滤镜**（材质 / 温度 / 光照 / 物种），指针停在哪儿，
旁边就浮出那一格的坐标、深度、材质或物种、能量、光照和温度。

---

## 这是什么

不是"一个有生命的游戏"，而是一个**会自己长出生命的盒子**。三条参考血统：

| 血统 | 代表作品 | 借什么 |
|---|---|---|
| 上帝沙盒 | WorldBox、The Powder Toy | 画笔式神力、灾害工具 |
| 进化模拟 | LifeEngine、The Bibites | 无设计的自然选择、形态自发演化 |
| 物质物理 | Noita、Evolving-Protozoa、ALIEN | 材质规则表、GRN 形态发生 |

刻意**不含**文明 / 王国 / 历史事件层。

## 世界的形状

**横板侧视剖面，有且只有一个重力方向（向下）。** 默认地貌是**海洋 + 岛屿**——大片水体，
散布几座岛屿，生物默认水生。

```
┌──────────────────────────┐
│  天空（约 30%）           │  ← 光从上往下射入，随深度衰减
├──────────────────────────┤
│  水体（约 36%）           │  ← 生物的主舞台：沙会沉、气会浮
├──────────────────────────┤  ← 水面线
│  基岩 / 沉积层（约 34%）  │
└──────────────────────────┘
             ↓ 重力
```

这个决定一次锁死三件互锁的事，所以它必须先定：

| 被它决定的东西 | 后果 |
|---|---|
| 材质规则 | 液体「下 → 左右」、气体「上 → 左右」、固体不动 |
| 更新顺序与并行 | 「自下而上扫描」+ 棋盘 4 相位（同相位分块互不相邻），都是为重力方向设计的 |
| 进化层难度 | 侧视下重力对所有生物都是负担——所以生物默认生活在水里 |

**为什么不是俯视（WorldBox 式）**：俯视下运动容易演化得多，但落沙层会退化成「涂格子」——
沙不会塌、水只能靠水位字段横向摊平，而且没有光梯度。材质层是这个项目的半个乐趣，不能丢。

**光梯度是侧视白送的机制**：生产者细胞必须待在浅水，而浅水正是掠食者的猎场。
垂直位置于是成为真实的生态位。

生成器在 `crates/core/src/worldgen.rs`（`sea_and_islands`）。

## 材质会动

七种材质（空 / 石 / 沙 / 水 / 火 / 气 / 残骸）各自只有**一张属性表**，
规则引擎只负责"按表执行"——加一种材质不需要动模拟循环的任何一行。

| 材质 | 行为 |
|---|---|
| 沙 / 残骸 | 向下落，斜着滑，**不横向找平** → 自然堆成 45° 休止角 |
| 水 | 向下落，斜着滑，被挡住就横向找平（一次最远探查 8 格） |
| 气 / 火 | 倒过来的液体：向上浮、向两侧扩散 |
| 火 | 12 tick 寿命；按可燃度概率点燃邻居；遇水熄灭 |

让路判定只有一条：**更重的挤开更轻的**。"目标必须是空或流体"保证沙丘能立住；
而**上浮不需要单独的规则**——气体顶不开水，但水能沉进气体里，
气泡上浮的真实机制是"上面的水塌下来"。

### 两个不显眼但必须写对的细节

**液体找平必须紧跟一次下落。** 最直觉的"侧邻空着就走"会让相邻两列水位 2/1
互相甩锅、**永远抖动**。后果不是"看起来有点晃"，而是分块脏标记永远清不空，
整个跳块优化直接失效。判据改成"目的地脚下必须能让开"之后，液面只能停在
"相邻列高度差 ≤ 1"——这正是离散网格上"平"的定义。

**世界之外不是空位。** `World::get` 对越界坐标返回 `Empty`（画笔拖到边缘时不该 panic），
但移动判定不能继承这个宽松。漏掉这条，浮到世界顶端的那层气会认为自己还能上浮，
沿着天花板左右滑动永不停歇。而且它只在真实地貌里显形——
人工搭的测试场景里没有那一层气。

> 这两个 bug 都归到同一类：**世界永远静不下来**。
> 它必须是一条测试契约，不是观感问题——一旦不成立，
> SPEC §2.4 的整个性能前提就没了。

## 光与热

世界多了一张**粗粒度**的场：`AIR_CELL = 4`，即每 4×4 像素一格。
512² 的世界对应 128×128 的场，一张 `f32` 表 64 KB。粗粒度的理由和 TPT 一样：
**光和热本来就没有像素级分辨率**，按世界分辨率算它是纯粹的浪费。
实测 512² 上一次「光重算 + 温度积分」是 0.9 ms + 0.7 ms，
而它们每 8 tick 各跑一次，摊到每 tick **0.2 ms**。

场里装两个量，**但它们是两种完全不同的东西**：

| | 光 | 温度 |
|---|---|---|
| 语义 | 布局的**纯函数** | **积分状态**（有记忆） |
| 更新 | 每 8 tick 从零重算 | 每 8 tick 在原值上扩散 / 注入 / 冷却 |
| 关掉所有光源 | 世界**立刻**变黑 | 慢慢降回 20 °C |

混成一张表会得到"关灯之后还亮着"的光照图——因为积分式更新会把上一帧的光
留在原地。所以 `light` 每次被清空重建，`temp` 才是原地迭代的。

**太阳是平行光，逐列行进。** 光在水里走 180 格衰减到零（`SUN_ATTEN`），
撞到不透明格就停。逐列意味着**硬阴影**：石头柱子后面是一条笔直的暗带，
不是柔和的半影。这是有意的——它让"柱子挡光"在光照滤镜里一眼可读。

**点光源是四向松弛两轮**（`→ ← ↓ ↑`，取四邻最大值减一格损耗）。
两轮足够覆盖 110 格的衰减范围，又不会把整张场拉平。

**遮挡只算材质。** 一格 4×4 里石头或沙占一半以上才算不透明。
生物**完全不参与**——顺带删掉了之前那套"大鱼给小鱼挡光"的常数，
那是凭空发明的，而真光场不需要它。

**温度有玩法**：`photosynthesis(T) = clamp(1 − ((T−25)/25)², 0, 1)`。
25 °C 附近产能满，两头衰减。寒潮第一次真的减产能，火第一次能"烤死"一片藻。

**火的温度改了三处才对。** 第一版一格火只让粗格升 20 度（读数 40 °C，看着像火是凉的）：
线性摊薄是错的（1/16 是 900 度的火焰、15/16 是 20 度的水，平均值没有意义）；
累加追不上扩散（每 8 tick 加一次、同时被拿走一半）；而且注入放在扩散**之前**，
刚设好的温度会被本 tick 摊掉一半（满格火只剩 623）。
现在是一格火 ≈ 356 °C、满格火 = 900 °C，注入放在最后。

**改过世界就要立刻重算场。** 场按 `tick % 8` 刷新，而**暂停时 tick 不走**——
画了一把火、把指针放上去，读数是 22 °C。所以任何改动世界的操作都置一个标记，
渲染前统一刷一次（1.6 ms，只在真的画了东西的那一帧付）。

**生产者读的是所在格的光，不是深度公式。** 以前是 `1 - depth / 180`，
现在柱子后面的生产者哪怕在浅水也是黑的。

### 一个补丁，但是必要的补丁

有了真光场之后，一条**搁浅在岸上的鱼头顶是满光照**——"离开水会死"直接失效。
所以要求锚点所在格的水占比 ≥ 35%（`SUBMERGED_MIN`）才算在光合。
这不是物理，是规则：光场回答"有多少光"，不回答"这具身体够不够得着水"。

### 为什么删掉了「环境容纳量」

那个常数当初存在的理由是"局部遮挡和领地都失效了，种群涨到 1737"。
它是个**按总数封顶**的阀门，而总数封顶几乎总是错的判据。
光场落地之后，限制种群的东西变成了**几何**：世界里有光的水格就那么多，
多一个生产者就多分走一份。8000 tick 实测 353 个生物、656 枚杀手、
能量账差额 0——不需要阀门。

## 四种滤镜

顶栏四个按钮（`V` 循环），互斥，TPT 式。滤镜走的是 **shader 分支**，
不是 CPU 重画世界——世界纹理存的仍然是语义键，滤镜只是在 `fs_main` 开头多一个 `switch`：

| 滤镜 | 画什么 |
|---|---|
| 材质 | 原样 |
| 温度 | 只看场，**完全忽略材质**（色带的关键点照抄 TPT 的 `heatTable`） |
| 光照 | 只看场，**完全忽略材质**（黑 → 深蓝 → 青 → 白） |
| 物种 | 材质压到 12%，物种色画在上面（`id × 137 % 360` 的色相） |

温度/光照"忽略材质"是有意的：TPT 里你看到的是**场的形状**，材质只是背景。
把材质混进去，"石头后面那条暗带"会淹没在石头的灰色里。

物种色用 `id * 137 % 360` 而不是随机数：137 和 360 互质，于是 id 连续递增时
色相在圆上均匀跳开，不需要维护一张调色板分配表。

两个渲染层的细节都容易踩：核心 WebGPU 的 `Rg32Float` **不可过滤**，
所以绑定时要写 `filterable: false`、shader 里只能用 `textureLoad` 自己做双线性；
而 `write_texture` 要求每行按 256 字节对齐。

> 想看一眼四张滤镜长什么样：`cargo test -p vivarium-render -- --ignored view_filter_preview_png`，
> 会写出 `target/view-{material,temperature,light,species}.png`。

## 世界是环形的（只对生物）

**左右边界首尾相接**：鱼从右边出去、从左边回来。材质层仍然是硬边界——
水不会从左边流出去又从右边流回来，因为材质层的分块并行依赖"两块之间至少隔一整块"
这个几何前提，一旦环绕就得把相位划分整个重做。

这条不是装饰。只给"往右"偏置的手工鱼会全部游到右边界堆成一团，
被领地规则卡住，种群停在 9 条——**表面看是生态平衡，实际是"所有鱼叠在一个角落"**。

环绕之后它们会自己散开，同时也暴露了一个更深的假象：局部遮挡和领地这两道负反馈
都是"位置相关"的，鱼一散开就同时失效，种群从 240 条涨到 **1737 条**。
当时补了一道全局负反馈（"环境容纳量"：生产者越多每个分到的光越少）。
**v0.24 把它删掉了**——有了真光场之后，限制种群的是几何：有光的水格就那么多。
按总数封顶的阀门看起来能稳住数字，但它同时也把"光不够"这件事的因果盖住了。

## 死掉的会烂掉

一格有机物可能有三种来历，而它们的**腐烂规则、运动方式、能不能吃**都不一样：

| 材质 | 来历 | 运动 | 会烂吗 | 能吃吗 |
|---|---|---|---|---|
| 碎屑 | 世界生成撒下的沉积物 | 粉末，会沉 | **不会** | 会 |
| 尸体 | 细胞死亡 | 粉末，会沉 | **会**（水里 20%/25 tick，空气里 3%） | 会 |
| 藻 | 海底长出来的 | **静止** | 不会 | 会 |

**为什么要拆成三种。** 早先它们全叫「残骸」，靠 `flags`（能量）猜身份：
`flags == 0` 被当成"饿死的尸体，可以烂"。于是**带能量的尸体永远不烂**——
实测残骸占比从 1.7% 一路爬到 3.3% 还在涨。而且"该不该还水"也没法判断，
吃掉天然碎屑时也把水还了回去，水位因此漂了二十格。

一个字段被塞了两种含义（"有多少能量" + "是什么东西"），这就是代价。

**腐烂规则搬到了生命层**，因为它要记账：尸体剩下的能量在腐烂时变成热量，
必须进 `dissipated`。材质层没有账本——它悄悄清掉一格带能量的尸体，
守恒断言就会报"多了 N 点"，而那个报错指向的是生命层，查起来毫无头绪。

顺带一个副产品：尸体和碎屑现在**颜色不同**。这不是装饰——"哪儿死过东西"和
"哪儿是海底沉积"是两种完全不同的信息，而它们的形状、密度、行为几乎一样，
颜色是唯一能区分它们的通道。

**空气里的尸体也会烂，只是慢七倍**（3% vs 20%）。概率给 0 就是一个吸收态：
鱼会游到水面之上的天空里死掉，那层尸体永远不消失——实测 8000 tick 堆了 4.3 万格。

天然碎屑永远稳定，所以没有生物的世界依然能完全静止。

## 藻是悬浮物

光只从上往下射，生产者只能待在浅水——于是"待在哪儿"有个平凡的最优解：
**待在最浅的地方**。行为网络没有需要权衡的东西，选择压力只能筛出"别沉下去"。

所以加了第二种食物：**悬浮在透光层水里的藻**。

| | |
|---|---|
| 长在哪 | **水面以下几格的水里**（不是海底） |
| 多快 | 每 25 tick 撒 30 格（通量是常数，和世界大小无关） |
| 多少能量 | 每格 **120**（必须压过"待在水面晒光"的 +26/tick） |
| 有多少 | 存量上限 700 格，实测在 283~700 之间振荡（被吃、又长回来） |

**位置是被两次失败逼出来的。** 长在海底时鱼**够不着**：海深 184 格，
一趟下潜往返的移动成本约 `13 × 368 ≈ 4800`，而一格藻只有 120 能量——
整片藻席吃下去也回不了本。改成"悬在透光层"之后，藻**是固体**，
3000 格就把水流切成碎块：`活跃块` 掉到 3/64、`移动 0`、全部鱼被顶进空气。

所以现在三个条件同时成立：

- **够得着**（长在透光层）——由生命层决定；
- **不挡路**（`is_solid() == false`，鱼能游进去吃）——材质层；
- **不切断水流**（能被水挤开）——材质层。

### 一个自己的移动规则：`MoveRule::Drifts`

| 规则 | 行为 | 谁在用 |
|---|---|---|
| `Static` | 不动 | 空、石 |
| `Falls` | 往下掉，按休止角堆积 | 沙、碎屑、尸体 |
| `Flows` | 往下、找平 | 水 |
| `Rises` | 往上、扩散 | 气、火 |
| **`Drifts`** | **不自己动，但会被更重的水挤开** | **藻** |

**为什么不给藻一个"上浮"规则。** 那要让它和上面的水换位，而水自己也在往下换位——
两格会永远互相换回来，分块脏标记永远清不空，跳块优化直接失效
（同一个陷阱 `try_spread` 里已经踩过一次）。被动让路没有这个问题：
藻只在"别人要过去"时挪，没人动它就静止。

**密度 3（比水轻）。** 水下沉时会把藻顶开，于是藻会慢慢浮到水面那一层——
这不是 bug，是"悬浮物"的必然结果。而且它只让**水**推：沙子落下来时不能和藻
换位，否则藻会被换到沙子上方那一格，而那一格可能是空气——藻飘到天上就下不来了。

**吃掉藻变回水。** 藻是水里的悬浮物，吃掉藻留下水，正是"把藻从水里滤掉"。
写成空位的话，每吃一格藻就少一格水。

> 前两次尝试都在这一节留下了痕迹：藻先是复用「残骸」（粉末，会掉下去），
> 后来是独立材质但静止（会挡路）。**"食物在哪"和"食物是什么"是同一个问题。**

### 嗅觉：四向射线

新增两路输入 `IN_FOOD_DIR_X` / `IN_FOOD_DIR_Y`（−1..+1）。沿四个方向各射一条 20 格的
射线，撞到固体就断（墙后面闻不到），找到含能量的食物就按 `1/距离` 累加一个方向分量。

射线是 80 格/生物/tick，扫方框是 1681；而且射线天然表达遮挡——一条鱼闻到隔壁岩架
后面的藻是没有道理的，它得绕过去。

> **一条分层教训。** 第一版为了让"闻着味道去觅食"真的发生，把嗅觉权重调到 8.0
> （远距离也能压过巡航偏置）。结果是**负收益**：种群从 52 掉到 37、细胞数从 688 掉到 442。
> 那不是参数没调好，是**在错的层解决问题**——手工基因组的职责是"会游、会吃、会生"
> 这条基线，不是替进化决定"该不该觅食"。权重压回 1.5 之后，只保证通道存在且方向正确，
> 要不要用、用多强，交给突变。

## 生物会活

一格要么是材质，要么属于某个有机体的某个细胞——**不能同时是两者**。
这条互斥规则由一张与材质表并列的占格表执行，材质层只读它（`World::yields_to`）：
细胞格的材质字段永远是 `Empty`，如果材质层只看材质，水会灌进鱼肚子里。

最小的鱼是三格：**移动 + 嘴 + 生产者**。但三格放大之后只是三个圆，
所以另外做了四种手工体型：

| 体型 | 格数 | 长什么样 |
|---|---|---|
| 银鱼 | 10 | 三排：背上腹下是生产者，中间一列移动细胞，前端两个嘴 |
| 叶背鱼 | 14 | 背上驮着一大片生产者，像一片会游的叶子；又重又慢，但晒得到光 |
| 蠕虫 | 12 | 细长分节，身体两侧挂着生产者节段；跑 2 格/tick，最穷的一个 |
| 水母 | 12 | 近似放射对称，嘴在正中间，四面都能吃；跑 2 格/tick，没有眼 |
| 掠食者 | 10 | 前端两枚杀手细胞像一对颚；唯一一种"收入不只来自光"的体型 |

**形状不是画着好看就行。** 生产者的边际收益在浅水里约 +14/tick，一个移动细胞要付 6，
所以一个体型能撑几个移动细胞大致就是「生产者数 × 2.3」。生产者太少会饿死，
太多则变成赚钱机器——繁殖快到瞬间铺满。`body.rs` 里有两条测试守着这个区间。

体型只按「朝右」画一遍，朝左时整个身体沿 x 镜像。**掉头是原地翻面，不是转身**——
二维精灵就该是这样，而且不翻的话，一条朝左游的鱼会把嘴留在尾巴那一侧。

| 细胞 | 干什么 | 每 tick 成本 |
|---|---|---|
| 生产者 | 把光转成能量，是唯一的"环境 → 生物"入口 | 5 |
| 移动 | 提供位移，没有它哪儿也去不了 | 4 |
| 嘴 | 吃邻格残骸 | 2 |
| 装甲 | 加重、不产出，只在小体型上做配重 | 1 |
| 眼 | 扩大感知范围 | 1 |

**活着很贵，而且光不够就活不下去。** 光从顶端射入、随深度线性衰减，
所以生产者必须待在浅水；深水里同样的鱼几十 tick 就饿死。
这条梯度是"生物为什么要浮上来"的全部理由。

**能量账是严格守恒的，并且可以直接断言**：

```
Σ 有机体身上的能量 + Σ 残骸蕴含的能量 + 累计耗散 == 累计注入
```

注入 = 太阳能 + 初始投放；耗散 = 维持成本 + 移动 + 死亡时的零头。
残骸的能量存在材质的 `flags` 里，所以残骸沉降、被水冲走时能量跟着走。
512² 跑 8000 tick、两百多条鱼生生死死，这条式子的差额是 **0**。

**行为是一张小网络**：15 路输入（前方有没有食物/阻挡/同类、四向阻挡、
能量比例、年龄比例、朝向、光照、**食物方向 x/y**）→ tanh 隐藏层 8 → 6 路输出
（左右上下 / 吃 / 繁殖）。
手工鱼的基因组是写死的，只做四件事：往前游、撞墙折返、看到尸体就吃、攒够能量就生。
**M2 到此为止——还没有任何东西在进化。**

### 生物占的那格水是「借」的

出生时身体占住一格水，那格水被**借走**；变成尸体时还欠着（尸体占着同一格）；
尸体腐烂或者被吃掉时还回来。于是「水 + 活细胞 + 残骸」是一个守恒量。

**为什么不把水「挤开」。** 早先的写法是把水推到附近的空位，推不下就顶到这一列
的水面之上（水面上升一格，下一 tick 自己流平）。听着更像物理，但它有一个致命后果：
**被顶上去的水成了下一条鱼出生的落脚点。** 一条鱼贴着水面生孩子，子代的水被顶到
亲代头顶；子代再生一个，新子代就站在刚才那格水上——每代往上爬三四格。

实测 512² 跑 8000 tick：水面从 y=153 被顶到 y=107，四十多条鱼骑在水面上，
既不能动也不能繁殖，整个种群冻死在那里。**被顶高的水位是不可逆的。**

配套还有一条：**生物必须贴着水**。移动和出生两道门都要求"身体四邻里有水或气"。
没有它，子代可以生在空气里，而光照越往上越亮——"往天上搬"永远有奖励、从来没有代价。
判据必须是"贴着水"而不是"自己身上有一格水"，因为**身体格的材质永远是 `Empty`**
（材质层与生命层的互斥约定）。第一版写成后者时，`stranded` 指标报出"全部 145 个
都飘在天上"——一个永远为真的指标比没有指标更糟。

> 这一类 bug 的共同点：**跑 100 tick 完全正常，跑 16000 tick 世界变了样。**
> 所以生态测试必须长跑，而且要断言**水位、残骸占比、飘在天上的个体数**这种硬指标——
> 能量账和生物数在崩坏发生时都是健康的。

## 身体是长出来的（历史：生长规则表）

> **这一节写的是 v0.28 之前的样子，规则表已经整个退役了。** 留着它是因为
> 它记着"为什么当初选了规则表"，以及那个选择在两年后怎么被推翻——
> 后来的事见下面的「身体是长出来的，而且是"段"长出来的」。
>
> 一句话剧透：规则表**赢了对神经网络的论证，输给了有界语法**。它拿分节、
> 附肢、对称去换了局部性，而实测证明局部性本来就不缺（改一个基因平均只影响
> 10% 的格）——**那笔交易不划算。**

默认的身体是五个手工设计的体型。加 `--morph` 之后，身体由一套**生长规则表**
从根细胞长出来：

```text
rules[代][母细胞类型][极性][生长的方向] = 子细胞类型（或者"不长"）
```

从根细胞开始做**广度优先**生长：每一格依次尝试四个方向（右、下、左、上），
能长就长，直到长满上限。全程没有随机数——同一个基因组必然长出同一个身体，
否则"遗传"就不成立。

**为什么是规则表，不是神经网络。** 真正的 GRN 是一张连续动力学图，
细胞的类型由它落在哪个吸引子上决定。听起来很美，但**改一个权重形状往往不变，
改十个权重形状可能崩掉**——那种基因型→表现型的映射对突变太不友好，
搜索会退化成随机游走。规则表正好相反：一个格子被改掉，形状就变一点点。

**四个维度，每一个都是被具体的形状逼出来的。** 第一版只有 `[代][类型][方向]`，
结果蠕虫表达不出来：它两侧各挂一个生产者，同为第 2 代的移动细胞，
一侧要往下长、一侧不要——同一格规则做不到。加"极性"（这个细胞是从哪个方向
生出来的）之后才通。

**热启动：从手工体型反推。** 从零随机搜索撞不出能活的形状，所以
`Grn::from_plan` 把五个手工体型反推成生长程序，长回来**逐格一致**。
于是"形态发生"和"手工体型"是同一套东西的两种写法，突变从这里出发去改。

**突变按"改几条"算，不按逐槽掷骰。** 规则表 16×7×5×4 = 2240 个槽，
5% 的逐槽概率会一次改掉上百条，身体立刻变成随机团。而且优先改**已经打开的**槽
——随机指的话绝大多数时候指到空槽，真正在用的那十几条永远不动。

| tick | 体型（格） |
|---|---|
| 8000 | **10–14**（四五个形状混杂） |
| 16000 | **10–10** |
| 32000 | **10–10** |

### 形状换到什么

形态发生接上之后暴露出一个问题：**形状其实没用**。细胞类型只影响维持成本、
重量和产出，"这几格摆成什么形状"几乎不参与任何计算——于是体型只是
"细胞数量的多重集"，突变把一格换掉就够了，它没有理由去改**布局**。

所以给两个细胞类型接上真正的功能：

| 细胞 | 换到什么 | 怎么算 |
|---|---|---|
| 移动 | **速度**（每 tick 走几格） | `1 + movers/4`，上限 3 |
| 眼 | **嗅觉半径** | `20 + 4×眼`，上限 32 |

**速度是要付钱的。** 每 tick 的移动成本 = `质量 × (速度+1)/2`：

| 速度 | 每 tick | 每格 |
|---|---|---|
| 1 | `1.00 × 质量` | `1.00 × 质量` |
| 2 | `1.25 × 质量` | `0.63 × 质量` |
| 3 | `1.50 × 质量` | `0.50 × 质量` |

"跑得快更烧钱"在**每 tick** 上成立（tick 制模拟里真正要权衡的就是这个），
而每格成本反而略降——多长移动细胞买的是"同样一份钱跑得更远"。

这一条落地时，蠕虫和水母（都跑 2 格/tick）各补了一格生产者才活下来。
水母补的那一格是**用眼换的**：它因此没有眼，嗅觉退回基础值 20。
**看得远是锦上添花，跑得动才是活着。**

**但结论是负面的，而且这个负面结论有用。** 机制接通了（有测试守着：
4 个移动细胞一 tick 走 2 格；1 只眼闻到 22 格外的食物、0 只眼闻不到），
可**最优体型没动**：

| | 16000 tick | 32000 tick |
|---|---|---|
| 手工体型 | 45 生物 / 614 细胞 / 体型 10–14 | 收敛到 **14** |
| 形态发生 | 41 生物 / 554 细胞 / 体型 10–14 | 收敛到 **14** |

两边都收敛到 14 格（6 个生产者的叶背鱼）。**诊断：新能力被"多长一个生产者"压倒了。**
生产者在光 0.8 下净赚约 +14/tick，而一只眼或两格移动换来的**间接**收益远低于这个数
——因为现在这个生态是**光照受限**的，不是觅食受限的：光就在头顶，不需要找。

所以"让形状有用"只做了一半：**梯度存在，但太浅**。要让形状真的被优化，
得让光本身不够养活一条鱼，把生态从光照受限推到觅食受限。

> **一个过程坑。** 第一版顺手把嗅觉基础半径从 20 写成 12（想着"基础 12 + 眼 4"
> 更整齐），结果所有无眼体型的嗅觉一起被砍，最优体型立刻从 10 格跳到 14 格。
> 那不是"形状有了梯度"，那是**削弱**——而且看起来完全像一次成功的实验。
> **加维度的时候不能顺手改已有的绝对值**，否则结果没法归因。

## 藻是生物，不是地上的东西

藻曾经是一种**材质**：悬浮、可吃、被水挤开、密度比水轻。那套东西能跑，
但每一条都在逼着补丁——能量要单独记一条注入通道（和 `inject_sunlight`
重复）、"被吃掉"要挤进 `eat_remains` 里和碎屑尸体抢位置、密度怎么调都不对
（比水轻会浮到水面把鱼也带上去，和水同重就变成水流的半固体障碍，
实测整个世界冻住）。

现在它是**一格生产者的单细胞生物**。三条别扭全部消失：

| | 材质时代 | 生物时代 |
|---|---|---|
| 能量来源 | 单独一条注入通道 | `inject_sunlight`（自动有容纳量制约） |
| 被吃掉 | `eat_remains` + 材质判定 | `eat_plankton`（能量转移） |
| 位置 | 由密度和水流决定（没法调对） | 自己不动，撒在哪儿就在哪儿 |

**"是不是藻"看形状**：一格生产者。不是新字段——工坊里画一个单格生产者
画出来的就该是藻。

**藻跳过行为网络**：它没有脑，几百个藻每 tick 各跑一遍 `sense` + `think`
是纯浪费。它的"行为"（不动、只繁殖）走一条比 `reproduce` 便宜得多的路径。

实测下来种群反而涨了（45 → 68）：材质时代的藻只会被"顺手吃掉"，
而生物藻会被**闻到**、被**专门去找**——鱼第一次有了真正的觅食行为。

## 建造细胞：维护结构

在此之前 `Builder` 是一个"付 6/tick、什么都不换"的格子：画上去只会让身体更穷。
现在它有一个真实的权衡：

> **每格建造细胞让整个身体的维持成本乘 0.8**（最多降到一半）。

| 身体 | 无建造 | 1 格 | 2 格 |
|---|---|---|---|
| 8 格（27/tick） | 27 | 25 | — |
| 14 格（45/tick） | 45 | 38 | 30 |

乘性而不是减固定值——身体越大，维护省下来的越多。代价是它只对大身体划算：
3 格的小鱼带一个，省下的 20% 还不够付它自己那 6 点。

## 生物不只有鱼

海草是 4 格竖直的生产者链，**一格也动不了**（没有移动细胞，
基因组里也没有方向偏置）。它扮演初级生产者——把光变成可吃的能量。

**但它不参与自动投放**，只能由玩家在工坊里亲手种。原因是实测的：

> 海草不动、不付移动成本、4 个生产者净赚 56.8/tick，比任何一条鱼都富。
> 放进轮换投放之后它指数增长到 **481 株**、把光全吃光，鱼一条不剩。

**固着生物在"按格数算产能"的模型里天然占优**——它省下了所有移动开销。

## 每一格都有一句说明

材质和细胞各有一句 `describe()`，写在**核心里**，界面两处共用：

- **底部调色板**：色块下面单独一行，显示当前选中材质的名字 + 说明。
- **生物工坊**：右侧面板最上面，显示当前画笔细胞的说明——放在最上面
  而不是藏在 tooltip 里，因为画身体时要反复问"这一格到底干什么用"。

写的是"**会发生什么**"，不是"它是什么"："水"这个名字已经说明了它是什么，
"会流动、能被挤开、生物要泡在里面才能活"才是要学的部分。

### 那行说明被控制台盖住了

玩家第二次报"提示还是挡住 UI"，并说明是**界面下方**、只看到控制台两行。
看起来像"控制台压住了描述"，实际是描述行**自己跑出了面板**。

原因很不起眼：竖直分隔线 `vsep()` 的高度写成了 `PALETTE_H - 16`——拿**面板**
高度当**行**高度。那一个元素把 `ui.horizontal` 的整行撑到 72px，描述行就被
推出面板底。而面板之间没有裁剪关系，溢出的部分不是被裁掉，是**被下面的
控制台盖住**（后画的赢）。所以第一反应"把 `PALETTE_H` 调高"是错的：
调到 88 只会让内容整体上移，溢出的那半行照样在。

两处一起改：`vsep` / `caption` 钉死在 `SWATCH + 16`，谁都不许引用 `PALETTE_H`；
`palette()` 末尾加一条断言，判据取**描述行自己的矩形**底部。

判据为什么只能取它，三条都实测过：

| 候选 | 结果 |
|---|---|
| `ui.min_rect().height()` | 被 `max_rect` 夹住：内容 67、面板 66，两者都报 66 |
| `ui.cursor().top()` | 含 `item_spacing.y`，正常布局下就已越过面板底 1px，判据永远红 |
| `desc.response.rect.bottom()` | 那一行实际占的位置，没有夹、没有间距 ✅ |

配一条量尺：`VIVARIUM_LAYOUT=1` 会打印"描述行还剩多少余量"。布局类问题只看
代码猜不准，但也不该为此改一次代码量一次。

**同一个坑的第二半在测试里**：`ui_preview` 的"中央必须是世界"原来只取世界区
正中间**一个像素**——而悬停读数框就画在那儿，底色恰好也是面板色。`PALETTE_H`
差 4px（世界区跟着挪 2px）就能让这个点从通过变成失败。改成扫一整条竖线、
要求 90% 以上不是面板色。

## 鱼在水里，而且在二维里游

两个都是玩家报的 bug，而且都不是"规则写错了"。

### "生物都在半空里飘着"

`touches_water` 是"生物默认水生"唯一的那条不变量，它被改过四版，
**每一版都对应一次能直接看见的故障**：

| 版本 | 判据 | 现象 |
|---|---|---|
| 1 | 任意一格的四邻有水 | 12 格的鱼整条浮在水面之上，只有尾巴尖蹭到水 |
| 2 | 表面邻格里水占一半 | **窄鱼**的侧面几乎总是水，头顶出水 4 格照样过半 |
| 3 | 每列头顶向上扫到水 | 对，但把气体和藻也算成水——藻会被顶到水面那一行 |
| 4 | **只认水和藻，且藻必须自己也在水里** | ✅ |

还有一条只在移动时成立的细节：判据**只查目标格，不查旧位置**。合并之后，
旧位置（在水里）会把新位置（在空中）盖过去，鱼可以一格一格往上爬。

### "生物只沿 X 轴移动"

手工基因组里**垂直方向从来没有正值**：`OUT_UP` 在浅水里恒为负，
而 `OUT_DOWN` 根本没有驱动。于是"往上是负、往下是零、往右是 +1"——
挑最大值的那个规则下，鱼只有两个方向可选。

改成**带设定点的双向趋光**：光高于设定点就往深处走、低于就上浮、
正好相等时垂直归零。三个数字都是测出来的：

| 数字 | 值 | 为什么 |
|---|---|---|
| 设定点 | 0.90 | 设成 0.60 时垂直占比 86%，但**种群从 60 塌到 5**——深处光不够，攒不出繁殖的 200 点 |
| 增益 | 12 | 要让水面处的下沉信号压过巡航偏置，需要 `tanh(gain × 0.10) > 0.76` |
| 巡航偏置 | 0.7 | **不能更低**：0.35 时 `tanh(0.35) ≈ 0.34` 只比移动阈值高一倍，而隐藏层的突变噪声能贡献 ±0.5——噪声把信号吃掉，85% 的 tick 里鱼根本不选方向 |

**还有一个把增益悄悄截断的 bug。** 突变里权重被 `clamp(-8, 8)`，而增益是 12——
第一代投放时一碰到那两个权重就截断成 ±8，`OUT_DOWN` 的激活值从 `+1.6`
变成 `-1.2`：鱼不但不下潜，还主动上浮。表里写 12、跑起来是 8，
而症状看起来完全像"行为规则写错了"。上限改成 16。

顺带修了 `IN_LIGHT` 的语义：旧公式 `1 - y/世界高` 把**世界尺寸**编进了信号，
同一个基因组在 64² 的池子和 512² 的海里表现完全不同（池子里鱼以为自己在
无光海底，一直想上浮、上浮到水面又被拦住，卡在那里一格不动）。现在改成
"从身体顶部向上数到水面有多远"，与世界大小无关。

## 生物会掉下来

不在水里的身体**每 tick 往下掉一格**。

在此之前，把鱼放在半空它会**原地冻结**——那不是"行为太保守"，是
**判据用错了地方**：

> 水陆判据回答的是"它能不能**游**"，不是"它能不能**存在**"。

`touches_water` 拦住所有主动移动是对的（一条在空气里的鱼不该横着飞），
但"被重力拉下去"不是主动移动。没有这个区分，半空的鱼会被永远钉在那里——
看起来像卡死，其实是每个方向都被拒绝。

所以 `try_move` 多了一个参数：

| | `Swim` | `Fall` |
|---|---|---|
| 水陆判据 | 拦 | **放行** |
| 能量 | 扣 | **不扣**（重力做功不是鱼在使劲） |
| 统计 | 计入 `moved[方向]` | 计入 `fell` |

**下落不扣能量**是关键：如果扣，一条掉进深水的鱼会因为"下落太贵"而卡在半空——
那是同一个 bug 的另一个版本。

**落在固体上会搁浅**：它仍然不在水里，既不能游也不能再生，但维持成本照扣，
于是会在原地饿死、变成尸体。那正是"鱼离开水会死"该有的样子。

> 生态里的 `落` 计数**长期是 0 才是对的**——它说明"不在水里"是罕见状态。
> 这个计数存在的意义是反过来用：如果它长期不是 0，说明水陆判据和实际位置对不上。

## 生物工坊

按 `W`（或左栏的方格图标）打开。左边选细胞、中间 16×16 网格上画、右边起名和按钮：

```
┌─ 生物工坊 ──────────────────────────────────────── 关闭 ┐
│ 细胞   ┌────────────────────┐   名字 [三节虫      ]  │
│ ▉ 嘴   │                    │   格数 9              │
│ ▉ 生产 │   16×16 网格画布   │   速度 2 格/tick      │
│ ▉ 移动 │   （点/拖连续落笔） │   嗅觉 24 格          │
│ ▉ 眼   │                    │   嘴 1                 │
│ ▉ 杀手 │                    │   ✓ 可以放置          │
│ ▉ 装甲 │                    │   [清空][居中]        │
│ ▉ 建造 │                    │   [放置到世界]        │
│ 擦除   └────────────────────┘   [存进生物库]        │
├──────────────────────────────────────────────────────┤
│ 生物库  [银鱼（3）] ×  [三节虫（9）] ×                │
└──────────────────────────────────────────────────────┘
```

**为什么是"画"而不是"调参数"。** 手工体型是写死在代码里的常量，想加第六个
就得改代码、重新编译——那不是"玩"。工坊把这件事变成点击。

**为什么是模态。** 画布本身就是一张网格，而窗口中央也是网格（世界）。
两个网格叠在一起、鼠标同时作用于两边，结果是"想画身体却顺手在世界里涂了一道水"。
遮罩必须自己吃掉点击：`pointer_over_ui` 不够——遮罩是**画上去的**、不是控件，
egui 不会把它算进去，于是点空白处会漏到世界上。

**合法性检查分两层。** 工坊知道"有没有嘴""超过 16 格吗""连不连通"（纯几何）；
"这一格是不是压在石头上"只有世界知道。所以"放置"是两段式：工坊里点一下，
再在世界里点一下决定落点。

**生物库是纯文本**，存在 exe 旁边的 `bodies/*.txt`：

```text
三节虫
0 0 2
1 0 2
0 -1 1
```

第一行名字，之后每行 `x y 细胞类型`。不引 `serde` 的理由很简单：要存的
只是十几个三元组，而纯文本还带来一个实际好处——**能直接打开看、能手改、能贴进 issue**。
代价是没有转义，所以名字要过滤掉路径分隔符（`../etc/passwd` → `___etc_passwd`）。

## 世界：新建 / 保存 / 读取

按 `G`（或左栏的地球图标）打开。在这之前，"换一个世界"只有两条路：改命令行
参数重启，或者按 `R` 换个种子——两条都不保留任何东西。

```
┌─ 世界 ─────────────────────────────────────── 关闭 ┐
│ 当前世界  512 × 512 · tick 28431 · 52 只 · 物种 17 │
│ ── 新建 ─────────────────────────────────────────  │
│ 宽   [=========|========] 512 格                   │
│ 高   [========|=========] 512 格                   │
│ 预设 [小 256×256] [标准 512×512] [大 768×728]      │
│ 种子 [20261016    ]（留空 = 随机）                 │
│ [x] 生成地形   [x] 随机投放初始生命（8 只）        │
│ 新建 / 读取会丢弃当前世界，未保存的进度无法恢复。   │
│ [新建世界]                                         │
│ ── 保存 ─────────────────────────────────────────  │
│ 文件名 [world-20261022] .vivarium        [保存]    │
│ 目录  C:\...\dist\saves                            │
│ ── 读取 ─────────────────────────────────────────  │
│ 名字             尺寸     tick   大小   修改时间    │
│ world-20261022   512×512  28431  1.0MB  刚刚  [读取]│
└────────────────────────────────────────────────────┘
```

**所有"会丢东西"的按钮都点两次，而且第一次点击就变红。**
新建和读取都会无声地毁掉当前世界，这里没有"另存为"兜底、也没有撤销——
世界不是文档，它是一段跑过的历史。第一次点"新建世界"不执行，按钮原地变成
红底的"确认丢弃当前世界"，三秒内再点才执行。

为什么不弹对话框：对话框会把"我点的是哪个按钮"这个上下文挡住。原地变红的话，
眼睛一直看着那个位置，看到的是"这个按钮现在会毁掉世界"。

两个**不同**的动作共用一个确认位，是这类交互最容易写错的地方：先点"新建"
再点"读取"，绝不能被当成"确认新建"。写错的后果是**点错按钮丢世界**。

**保存不需要确认。** 存档是唯一应该被鼓励的动作。

### 存档是二进制，判据是"读回来逐 tick 一致"

`.vivarium` 是一个世界的完整快照，存在 exe 旁边的 `saves/`（沿用 1.x 的
"导出落程序目录"惯例——玩家不该为了找自己的存档去翻 `%APPDATA%` 下面那串
哈希目录名）。

判据只有一条：**读回来之后继续跑，必须和从没存过档逐 tick 一致。** 所以下面
这些看着"像缓存"的东西也必须存进去：

| 存 | 为什么 |
|---|---|
| 随机数发生器的**当前位置**，不是种子 | 只存种子会回到序列开头，同一段随机数被用两次 |
| `next_id` | 它进 `World::hash`（占格表里存着有机体编号） |
| 温度场 | 它是**积分状态**，不是布局的纯函数 |
| 每个细胞的 `wet` | "出生那一刻借了几格水"的债务；丢了它，读档后每具尸体都按"此刻泡不泡水"重算，水位开始慢慢漂——而画面看不出任何异常 |

**光照不存**：它是布局的纯函数，读档时按装回去的材质重算一遍就行。

**尾标记（`ENDVIVAR`）不是仪式感。** 截断的存档是最常见的坏档（磁盘满、
进程被杀、手滑复制了一半），而少了它，"读到一半没数据了"和"文件本来就这么长"
无法区分。

**先写 `.tmp` 再改名。** 写一半被中断留下的半截文件如果顶着正式文件名，
下次读档会得到一个"少了半条鱼"的世界，而玩家以为那是自己的存档坏了。

实测（512²，跑满 2000 tick，623 只 / 5066 格细胞）：

| 项 | 实测 |
|---|---|
| 存档大小 | 1 021 694 字节（1.0 MB） |
| 逐格裸存材质 | 524 288 字节（材质段压到约 1/5） |
| `encode` / `decode` | 6.0 ms / 4.6 ms |

**材质段压了 5 倍，而生物一多，存档的大小就由基因组决定**——每条鱼 300 个
权重就是 1200 字节，623 条就是 750 KB。想让存档更小，该动的是权重，不是材质。

### 列表只读文件头 32 字节

一行要显示的只有名字、尺寸、tick、大小、修改时间——全在文件头里。把整个世界
读进来只为显示一行文字，在 2000² 的档上是几百毫秒 × N 个文件。

读不出头的文件**直接不进列表**：一行点开就报错的条目，不如让它彻底消失，
玩家至少不会以为"我存的东西还在"。

修改时间显示**"多久以前"**（"3 分钟前"），不是绝对时刻：绝对时刻要时区，
而时区要一张随系统设置变化的表；而"哪个是最新的"恰好是玩家真正想问的问题。
默认存档名用的是**本地**日期——晚上十点存的世界，按 UTC 已经叫
`world-20261023` 了。

### 世界尺寸不必是 64 的倍数

"世界尺寸必须是 64 的倍数"这条约束，是从"整块拷贝"这个**实现**里长出来的，
却写进了**接口**。代价是玩家想开 600×450 时，唯一的出路是偷偷凑成 640×512——
而多出来的那一条会在画面上出现、在水位统计里出现、在相机取景里出现。

现在分块允许"最后一行/列是残块"，`chunk_w(cx)` / `chunk_h(cy)` 给出每块的真实
宽高，材质层所有步长都用 `ws.w` / `ws.h`。验收是一条等价性测试：100×68 的世界
（两列残块、一行 4 格高的残块）里，跳块扫描和全扫逐 tick 逐格相同。

顺手挖出一个**既有** bug：一次移动的横向找平半径是 8 格，而脏块晕影只有 1 格，
于是"某格变了"传不到 8 格之外那个因此变得可动的格。`git stash` 回到改动前的
代码，同样的场景在同样的 tick 117 分叉——所以它不是这次改出来的。修法是把
`DIRTY_HALO_X = 8` 和 `LATERAL_REACH = 8` 用编译期断言绑在一起。

## 身体是长出来的，而且是"段"长出来的

旧的形态发生是一张 `rules[代][母类型][极性][方向]` 的规则表，从根细胞出发
BFS 生长。它能跑，但有三个结构性问题：

1. **没有"位置"这个维度**。同一个类型的细胞在不同位置想长不同的东西，
   只能靠"第几代"近似，而 BFS 步数和几何位置没有稳定关系。
   **所以它表达不了"分节"**——而分节是所有多细胞身体的第一块砖。
2. 改 `rules[0]` = 改根细胞的 4 次分裂 = 整个身体重画。
3. 深度是整数，加一代可能让身体翻倍，也可能一格不长。

实测 20 个变异体**全部是"3~10 格、包围盒最大 5×3 的一团"**。
有意思的是：局部性其实不差（改一个基因平均只影响 10% 的格），
**缺的是表达力，不是可搜索性。**

所以现在换成两层，**正交**：

```
布局（哪里有格）    Segment 树 —— 段 + 重复 + 镜像 + 子段
类型（这格带什么）  Gradient  —— f(沿主轴位置, 到边界距离) → 细胞器
```

**重复给体节，镜像给成对器官，子段给附肢。** 这三件事就是全部的表达力来源。

### 发育分两步，严格分开

```
步骤 A（纯几何）：Segment 树 → 一组 (offset, base)
步骤 B（位置解释）：每个格算 (along, from_edge) → 最终细胞器
```

分开之后，**改梯度不挪动任何一格，改布局也不打乱任何类型规则**。
这就是"模块化"在代码层的落地——而且"改一个基因影响多少格"可以在
步骤 A 单独测量。

### 类型由"梯度"决定，不由"查表"决定

这是 Wolpert 的 French flag model：

```
沿主轴位置 < 0.35        → 生产者
沿主轴位置 > 0.35 且贴边 → 嘴
最外一圈                 → 装甲
```

改一个阈值 → **整片同质区域一起平移，而且比例保持**。身体变长的时候头不会变大。
这就是"少量基因改动 → 协调的表型"。

而且阈值是连续标量，映射到离散网格时**天然多对一**——所以"大部分变异是中性"
这件事不需要额外实现，它是梯度的副产品（简并度 2.70 → **5.26**）。

### 实测

| 判据 | 规则表时代 | 段树之后 |
|---|---|---|
| 简并度（基因组数 / 表型数） | 2.70 | **5.26** |
| 模块化（改一个基因影响多少格） | 10%（spread 0.14） | **14%（spread 0.11）** |
| 表型空间 | 全是 3~10 格、最大 5×3 | **8 / 10 / 19 / 20 格，5×3 与 10×3** |

```
[seed 15] 20 格 · 1 段 · 包围盒 10×3 · 连通 · 杀手 7 · 生产者 7 · 嘴 3 · 移动 3
           ...PS...PP
           MMMDSSSSDD
           ..PPS..SPP
```

**两节体节**——这是规则表从来没长出来过的东西。

**诚实的部分**：体节（`repeat`）成了，成对器官（`mirror`）和附肢（`children`）
在 30 次随机变异里没观察到。而 30 次随机变异**不是演化**——真正的验证要跑
8000 tick 让选择去筛。

## 地形太陡，鱼只会沿着崖壁蹭

这件事最早是被"看起来像 bug"的现象报上来的：水里的生物只朝一个方向游，
撞在石壁上。

量了一下才明白它不是行为问题，是几何问题。旧地形的母题是"海床漂移 +
几座高斯钟形岛"：岛必须从海底一路堆到水面以上，而水深是固定的，
于是**唯一能调的就是岛的宽度**。半宽 42 列时剖面最陡 **17 格/列**，
84 列里有 38 列超过 1 格/列。

而移动是**四向离散**的：相邻高差 > 1 就是一道必须靠纯垂直越过的墙，
17 格意味着至少 6 个 tick 全部向上、全部在付能量。鱼学不会，
就沿着崖壁一直蹭。

**加宽岛屿只能把 17 变成 4，还是墙。** 所以换母题：

| 旧 | 新 |
|---|---|
| 海床随机游走 + 钟形岛 | **fBm 高度场**（3 个八度值噪声） |
| 岛宽随机 | **按分位数切海岸线**（恰好 50% 的列在岸上，不是抽奖） |
| 岛高 = 水深 × 随机倍率 | **一个比例尺，从坡度上限倒推** |
| 无 | **热力侵蚀**（逐列把超过上限的高差搬给邻居，迭代到收敛） |

验收从"看起来平缓"变成一个可断言的数：**100 个种子 × 三种尺寸，
`max(|surface[x+1] − surface[x]|) ≤ 2`，一个都不许超。**

### 两个被数据纠正的判断

**① 最陡的地方不是深海，是海岸线。**

第一版给陆地和大海各用一个比例尺（各自归一化到"能抬多高"/"能有多深"），
结果海岸线处有一个**折角**：同一格高差，陆侧放大 167 倍、海侧放大 318 倍。
实测最陡的 4 格/列就出现在那条线上。

**折角才是问题，深度不是。** 改成一个比例尺之后映射在切点处 C¹ 连续，
坡度上界只剩"高度场导数 × scale"，于是 `scale` 可以直接从约束倒推：

```
scale = min( 3·span/d_elev,          // 坡度
             (waterline−2)/(1−cut),  // 陆地不能顶出世界
             (h−waterline−2)/cut )   // 海不能穿底
```

那个 **3 是故意的乐观**：`d_elev` 是导数的最坏情况，而真实剖面上达到
最坏值的只是很短的几段，侵蚀几轮就磨平了。按最坏值定会把地形压得过矮——
实测海只有 70 格深，生物数从 692 掉到 234。

**② 侵蚀必须用快照增量，不能就地改。**

就地改的结果依赖遍历顺序（从右往左扫和从左往右扫不一样），表现是
"所有坡都朝一个方向"——看起来完全像噪声生成写错了。有测试钉着：
一段对称剖面侵蚀之后必须仍然对称。

### 代价：水少了 6 倍

| | 旧地形 | 新地形 |
|---|---|---|
| 剖面最陡 | 17 格/列 | **2 格/列** |
| 最深 | 184 格 | 159 格 |
| 有水列平均水深 | ~150 格 | **35 格** |
| 水格占世界 | ~16% | **3.4%** |
| 生物数（8000 tick） | 692 | **258** |

**生物数掉了 2.7 倍，因为水体积掉了 6 倍。** 这是几何的必然：坡度 ≤ 2 时，
海的深度上限由水平跨度决定，而 512 高的世界里"坡缓"和"海深"是互斥的
（比例尺还被陆地那一侧卡着——陆地不能顶出世界）。

想要两者兼得，得用**更宽**的世界：`d_elev ∝ 1/w`，世界越宽坡度越小，
同样的坡度能换更多起伏。这是「世界」窗口里能自己调的。

**但这个取舍是对的。** 目标是"为生物向陆地发展做准备"，需要的是宽阔平缓的
海岸，不是深不见底的海。而且浅海让光能照到海底，生产者铺满整个海床——
这恰恰是陆地演化的起点。

## 基因型和表型脱钩了 8000 tick

段树接上之后，我按设计文档的承诺跑了一次 8000 tick，让选择去筛身体。
结果的第一行就不对：

```
tick  8000  活 801  格 平均 7.8 最大 10  代数 158  表型    3 基因组  647 简并 215.67
```

**表型只有 3 种，基因组有 647 种。** 看数字像"中性网络极其发达"——
647 个不同的基因组长出同样的 3 种身体，多么漂亮的简并。

真相是它们**根本没接线**。`reproduce` 里写着：

```rust
let cells = parent.cells.clone();   // ← 子代继承父代当前的身体
```

子代继承的是父代**当前**的身体（连被咬掉的缺口一起继承），而基因组
一路漂移。所以身体形状只在最初投放时由基因决定，之后两万代都不变。
那 647 个基因组映射到 3 个表型，不是因为简并，而是因为**表型不是基因组决定的**。

改成一行：

```rust
let cells = genome.body.develop();   // 子代的身体由它自己的基因组长出来
```

同一个世界、同一个种子、同样 8000 tick：

| | 表型 | 基因组 | 简并度 | 最大格 |
|---|---|---|---|---|
| 脱钩 | **3** | 647 | 215.67 | 10 |
| 接线 | **522** | 937 | 1.80 | 24 |

**表型从 3 涨到 522。** 这才是"扩空间"真正落地。

顺带一个必须改的地方：造价要按**子代**的格数算。按亲代算的话，"变异让身体
变大"就是白送。改成按子代算之后，身体从 12.0 格缩到 6.2 格——
**"变大要付钱"第一次真的起作用。**

### 然后选择把附肢删掉了

| tick | 分节 | 镜像 | 附肢 | 段数均值 |
|---|---|---|---|---|
| 1000 | 179 | 184 | 56 | 1.22 |
| 3000 | 426 | 398 | **292** | **7.77** |
| 8000 | 907 | 643 | **26** | **1.64** |

**分节（89%）和成对器官（63%）活下来了，附肢从 292 掉到 26。**

这不是 bug，是模型在说实话。设计文档里写过一段预期，当时只是推理：

> 分支在真实生物里主要服务于运动（肢体）和交换（肺、鳃、肠）。但这里
> 运动是"整个身体平移一格"，肢体不提供杠杆；交换靠"相邻格"，分支增加的
> 只是表面积。

8000 tick 之后选择给出了同一个结论，而且更狠：**附肢的 upkeep 是真的，
杠杆是假的。** 所以它被删掉了。

### 身体必须连通，而且顺序不能反

同一次测量里还看到过这种身体：

```
...PP..SSS
MDSDDMESDS
..DPE..DPS
..........
MD..M.....
```

包围盒 10×5，中间空一行，**散架成 3 块**。不连通的身体在物理上是荒谬的：
`try_move` 只逐格验通行，中间那道墙根本不参与判定，于是它能**穿过一格厚的石头**。

所以发育里加了一条规则：**只留和根那一格 4-连通的部分**。
和真实胚胎里失去接触的细胞凋亡是同一件事。

但这里有个顺序陷阱：**先截断到 `max_cells`、再取连通块**。
反过来不行——一个段自己的 `cells` 是任意几何（比如四格菱形），
截在中间只剩两个对角格，而**对角相邻在 4-连通意义上不算连着**。
所以"先过滤再截断"会被截断重新切断，而且看上去完全正常。

---

## 细胞是一个位掩码，不是一个名字

这一条改的是"细胞是什么"这个最底层的东西。

以前 `CellType` 是七个枚举变体。加一种细胞要改七处 `match` + 存档升版 +
进化池变大；而"进化发明一种新细胞"在**类型系统层面**就不可能——
`random_kind` 只能从 `ALL` 里挑，挑不出一个还没被写进代码的类型。

现在是 11 个 bit：

```
bit 0-1   叶绿体    level 0..=2   ← 可数
bit 2-3   鞭毛      level 0..=2   ← 可数
bit 4-5   刺细胞    level 0..=2   ← 可数
bit 6     消化液泡  0/1
bit 7     装甲板    0/1
bit 8     气囊      0/1
bit 9     眼点      0/1
bit 10    线粒体    0/1（默认 1）
```

功能由**组合**决定，不由枚举决定。于是"新类型"是涌现的：

| 组合 | 涌现出的"类型" |
|---|---|
| 叶绿体 | 生产者 |
| 叶绿体 + 装甲 | 硬壳藻 |
| 叶绿体 + 气囊 | 漂浮的藻垫 |
| 鞭毛 + 刺 | 冲锋的捕食者 |

没有人写"叶绿体 + 装甲 = 硬壳藻"这条规则。是 `upkeep` 加性、`density` 平均
这两条算出来之后，**这个组合自己变成了一种活法**。

### 变异从"跳崖"变成"走一步"

| | 结果 |
|---|---|
| 从 5 个枚举里重抽（旧） | `Mover` 变成 `Producer`——**功能整体换掉，形状没变** |
| 翻一个 bit（新） | `鞭毛` → `鞭毛 + 气囊`——**其他部分完全不变，只多一个能力** |

**重抽是跳崖，翻 bit 是走一步。** 300 维权重空间的随机游走已经够糟了，
形态空间还在跳崖——这就是"进化从没长出新东西"的直接原因之一。

### 三条必须定死的语义

**`upkeep` 加性，`density` 加权平均。** 加性表达"一格干两件事付两份钱"；
密度如果也加性，气囊（0.15）永远压不过装甲（1.35）——**平均**才让
"10 格里塞 3 个气囊就能浮起来"成立。

**等级超线性**（`base × level^1.2`）。不这样的话"一格 2 级叶绿体"严格优于
"两格各 1 级"：省一半体积、被吃面积一半、移动质量少一半，每一项都不差。
于是所有生物都会堆满等级，"多长一格 / 长成什么形状"这个维度就废了。

**线粒体默认开、可被关掉，关掉后主动细胞器降到 25%。** 恒为 1 的开关不是开关。
25% 而不是 0，因为完全关闭是跳崖式变异。而装甲和气囊是**被动结构**，
本来就不需要能量——于是一个纯装甲身体可以全身不带线粒体、`upkeep` 极低，
**它就是一块石头**，动不了、吃不了、产不了能，只会被啃。这正是它该有的命运。

## 生物有记忆了

`INPUTS` 从 17 涨到 22，多出来的是五路**状态**，不是新的感知：

```
IN_PREV_LEFT / RIGHT / UP / DOWN   上一 tick 的输出
IN_STUCK                           连续几 tick 没走动
```

前四路喂回 `last_out`。严格说这不是"学习"，是**状态**——但它买到的东西
正好是原来缺的：惯性巡航、撞墙后转向、节律行为。

没有它，`think()` 是纯函数，**同样的处境永远给同样的反应**——一个"向右"
权重稍大的个体，会永远向右、永远撞墙。这就是"只朝一个方向游"的一半原因。

**它不破坏谱系**：遗传的仍然只有基因，一生的经历不进基因。

## 能斜着走了

`pick_direction` 原来从四个方向里取 argmax，**斜向根本不存在**。
现在：主方向仍然是 argmax（保住现有调参），但**与它垂直的那个方向也超过阈值**
时，就叠加成斜向。

配合"坡度 ≤ 1 的地形"，这就是**顺坡移动**的全部实现——不需要任何"贴坡"逻辑：

| 相邻列高差 | 需要什么动作 |
|---|---|
| 0（平地） | 水平 1 格 |
| **1（45°）** | **水平 1 + 垂直 1** ← 斜向 |
| 17（现在的崖壁） | 垂直 17，不可能 |

斜向不是白给的：次方向必须**自己也超过阈值**。所以平地上巡航还是直线，
85% 的移动仍然是直线的（实测 8000 tick，斜向稳定在 **15%**）。

还有一个所有 8 向网格移动都要写的判定：**不能穿对角缝**。两个正交邻格都是墙时，
斜向必须被拒绝——否则一条 1 格厚的墙看着完好，生物却过去了。

## 水不是墙

这一条是"细胞数太多，鱼浮不起来"的真正原因，而且它比"浮力不够"粗暴得多。

```rust
// 旧代码，life_sim.rs
MaterialKind::Water => body <= SMALL_BODY_MAX,   // 16
```

**17 格以上的身体在水里，水是固体。** 不是"推不动"，是**进不去**。症状是一条
完整的链：通行判定全部失败 → "身体碰不到水"也跟着失败 → 重力接管 → 一路掉到
海底 → 搁浅 → 维持成本照扣 → 饿死。

而 `SMALL_BODY_MAX = 16` 的注释写的是「`try_move` 的搬运代价是 O(格数²)，
16 格时是 256 次比较，可以忽略」。**一条性能约束被写成了世界法则**——
和「世界必须是 64 的倍数」是同一类错误，第三次了。

它给的理由是"1000 格的生物移动会推走 1000 格水，行为和性能都会崩"。这个担心
**当时**成立，现在不成立：身体格数上限是 `MAX_BODY_CELLS = 24`，一次移动最多
swap 24 格水，是 O(n)。**那个数字守的是一道已经不存在的门，而它自己变成了一道
新的墙。**

拆掉之后的实测（512² · 种子 11 · 12 条起步 · 8000 tick）：

| 体型 | 存活 | 最大 | 平均 | 每条平均能量 | 累计下落 |
|---|---|---|---|---|---|
| 14 格 | 859 | 14 | 11.7 | 1940 | 2280 |
| 18 格 | 873 | 18 | 15.1 | 3404 | 884 |
| **24 格** | 784 | 24 | 19.6 | **4824** | **783** |

**24 格的身体不但活着，每条的平均能量还是 14 格的 2.5 倍。** 所以"大身体活不
下来"从来不是能量问题，是那道墙。大身体"在水里更累"这件事，现在由
`move_cost` 的质量项表达——那是连续的代价，不是一道墙。

### 但它顺手挖出一个新问题

产能按**格数**算，不按**受光面积**算。所以每多一格生产者就多一份收益，
而加性 `upkeep` 永远小于收益——**堆叠是免费的**。

于是体型进化只有一个方向：越大越好。`MAX_BODY_CELLS = 24` 会变成所有生物都
顶到的天花板，而不是一个分布。解药是"产能按暴露表面积算"（上方有遮挡就不满产），
它本来是给植物用的，现在同时是**体型多样性的必要条件**。

## 上岸：从"开关"改成"成本"

在这之前，水里和岸上是**两个世界**，中间隔着一道判据：

```rust
// 旧代码，try_move 里
if kind == MoveKind::Swim && !Self::touches_water(world, org.width, &targets) {
    return false;   // 身体必须整具在水下才游得动
}
```

它挡住了一个真实的问题——光越往上越亮、空气可通行，于是"往上"永远有奖励、
从来没有代价；实测 5000 tick 就有个体停在水面上方 25 格，能量晒满、
不能动也不能繁殖，整个种群随之冻死。

**但它用错了手段。** 它把"上岸"变成一件**不可能**的事，而陆地演化需要的
是"很贵但可行"。现在换成三件事：

| 机制 | 内容 |
|---|---|
| **移动加价** | `cost × (1 + 3 × (1 − 水占比))`——全脱水时贵 4 倍 |
| **支撑成本** | `+ 质量 × 0.5 × (1 − 水占比)`——站着不动也要付 |
| **光合打折** | 水占比 0.05 以下零产，0.05~0.35 线性爬升 |

前两条是"上岸多贵"，第三条是"岸上能不能活"。**光合那条是这一轮真正的改动**：
原来是 `water_frac < 0.35` 直接跳过，也就是"要么满产、要么零产"——而那条
悬崖**正好落在海岸线上**，于是"半上岸"在能量上根本不存在，陆地演化只能
是一刀切。现在潮间带有了 0~100% 之间的连续产能，一共 6 行：

```rust
pub fn dampness(water_frac: f32) -> f32 {
    if water_frac <= DRY_MIN { return 0.0; }
    ((water_frac - DRY_MIN) / (SUBMERGED_MIN - DRY_MIN)).min(1.0)
}
```

### 拆了门，天上的鱼会不会回来

不会，因为有三条同时管着：**空气里零光合**、**每步贵 4 倍**、**重力每 tick
拉一格**。只拆不补才会飘——这三条缺一条都不行。

实测（512² · 种子 11 · 16 条 · 8000 tick）：`离水` 个体 0~4 只，最高的个体
锚点 **y=129**，而水面线是 **y=128**。一 tick 都没飘上去。

### 大身体更难上岸

两个 mass 项都是乘性的，所以"身体越大越上不了岸"自动成立，不需要写任何
"如果身体大就……"的规则。实测（3000 点能量，站在干石头上）：

| 身体 | 存活 |
|---|---|
| 3 格 | 201 tick |
| 12 格 | 51 tick |

**差 4 倍**，方向也对。

### 一个没预料到的结果：生物数 258 → 581

上一轮换地形之后生物数从 692 掉到 258，当时的解释是"水体积掉了 6 倍"。
**那只对了一半。**

真正的限制是"水面那一层不可用"：旧判据要求整具身体都在水下，于是一条鱼
头顶出水就一格也动不了，重力把它压下去、它再游上来——一个每 tick 都在
烧钱的极限环。现在它能贴着水面游，而水面恰好是光最强的地方。

| | 门在 | 门拆了 |
|---|---|---|
| 生物数 | 258 | **581** |
| 平均体型 | 6.3 格 | 4.6 格 |
| 斜向占比 | 7.0% | 10.6% |

体型变小不是因为选择换了方向，是因为**个体变多了**：同样的光要分给更多张嘴。

### 但一只都没有真正上岸

8000 tick 里最高的个体一直在水面上下一格。**这符合预期**：岸上没有任何
食物，上岸只有成本没有收益。要等"陆生光合"（让岸上也能产能）和足够的
捕食者压力，陆地才会真的被用起来。

**不要因为这条没发生就以为这一步没做好。** 这一步交付的是"可行"，不是"发生"。

## 工坊：能发明细胞，也能把它存下来

细胞的行为从 v0.26 起就全部由 `organelles` 位掩码决定，而工坊一直在画
**类型枚举**——那半个功能是缺的。

现在：

- **右侧「细胞器」面板**：叶绿体 / 鞭毛 / 刺 点一下 0→1→2→0（等级终于能编辑），
  嘴 / 装甲 / 气囊 / 眼 / 线粒体 / 建造 / 根 点一下翻转。
- **左侧「我的」一列**：把当前画笔存成一个自定义细胞，点一下就能再用。
  存在 `bodies/cells.dat`，重启还在。**右键点条目删掉它。**
- **画布右键 = 擦除**。原来那个「擦除」按钮删了——画画的人对"右键擦"有肌肉
  记忆，而**一个状态如果能由手势表达，就不该占一个开关**。

于是「叶绿体 + 气囊」（漂浮的藻垫）这种预设里没有的组合，第一次能被画出来、
存下来、放进世界。**能改位掩码就等于能发明新细胞。**

## 建造细胞到底有没有用

有，但只有一个作用：**降低整具身体的维持成本**。每多一格建造，全身体维持
成本乘 0.8，最多降到一半（所以它只对大身体划算，这是刻意的）。

不过它原来是按 `kind` 数的，而工坊能拼组合之后有个坑：

```
"叶绿体 + 建造" 的 kind = Producer   ← primary_cell_type 里叶绿体排在建造前面
→ 按 kind 数一个建造细胞都数不到
→ 玩家画了建造，却拿不到折扣，而画面上完全看不出原因
```

改成按 `organelles.has(BUILDER)` 数。**和"尸体要留能量"是同一类：
行为该读位掩码，不该读那个有损的"代表类型"。**

## 尸体是零卡路里的（所以没有食腐动物）

海洋里一直在下尸体雨：8000 tick 里 **14,824 次死亡、137,411 格尸体**。
但统计下来：

| | |
|---|---|
| 尸体格里能量为 0 的 | **61%** |
| 剩下 39% 的平均能量 | **5 点** |
| 全部尸体 ÷ 账本注入 | **0.18%** |

**一格尸体够一个嘴活一个 tick。** 食腐在这个模型里不是"效率低"，是数学上
不可能存在——而食腐是真实海洋里最大的能量回收通道之一。

### 根因：一个池子既是脂肪又是身体

饿死的定义就是"把能烧的都烧完了"。而 `energy` 同时扮演"储备"和"身体"，
所以**饿死 = 把自己烧成 0**，尸体自然是空的。而饿死是主要死因。

### 改法：给身体单开一个账户

```rust
pub struct Organism {
    pub energy: u32,      // 脂肪：付维持、移动、繁殖，会烧完
    pub structure: u32,   // 生物量：身体本身，烧不掉
}
```

- **从收入里划**：每份收入（光合 / 进食 / 捕食）的 1/8 转成生物量。
  生物量是光合作用固化下来的能量，所以它该从**收入**来，
  不是死亡那一刻凭空加上去。
- **上限是造价**：`BIRTH_ENERGY_PER_CELL × 格数`。一具身体最多值回它的造价。
- **尸体价值 = 脂肪 + 身体**，`bury` 把它摊到每一格。
- **捕食者拿现金，食腐者拿房产**：捕食只转移猎物的脂肪，身体留在尸体里。

| | 之前 | 现在 |
|---|---|---|
| 尸体格平均能量 | 5 | **38** |
| 带能量的尸体格 | 39% | **97%** |
| 尸体总能量 ÷ 注入 | 0.18% | **2.4%** |
| 动物数（三种子平均） | 311 | 305 |

**13 倍的尸体能量，种群几乎没动。** 那个 1/8 的税被"生物量满了就不再划"
抵消了：活得够久的个体，后期全部收入都进能量池。

三个副产品：**活得久 = 值钱**（老个体从纯负担变成资源）、
**杀幼崽和杀成体有区别**（子代生物量从 0 开始）、
**陆地食物链的第一块砖**（岸上要有东西吃，动物才可能上岸）。

## 工坊不再强制"必须有嘴"

原来的判据是 `mouths > 0`，理由是"没有嘴就吃不了东西"。但那句话只对了一半
——**生产者自己就能产能**。而纯生产者身体（海草）不但能活，实测还是超模的：
它省下全部移动开销，4 格净赚 56.8/tick。**这条门一直在挡一个强策略。**

现在判据是"**至少有一种能量来源**"（生产者或嘴）。仍然拦"既不能产能也不能吃"
的身体，但话改成「没有能量来源——它只会慢慢饿死」。

## 放在陆地上的鱼为什么会"凭空消失"

往陆地上一放，它落下来、挣扎两秒、然后**一格东西都不留**。看起来像 bug。

它确实是 bug，但不是"消失"那一步——它先饿死了（陆地上没有水，光合产不出
能量，而陆地上还要多付支撑成本）。真正错的是**死后什么都不留**：

```rust
// 旧代码，bury 里
if cell.wet {
    world.set(x, y, remains_of(cell.kind));   // 留尸体
}
// 干细胞的份额……什么都不留
```

一个 `if` 同时管了两件事：**要不要留尸体** 和 **要不要还水**。而它们是两件事
——`Cell::wet` 是"出生那一刻借了几格水"的债务，尸体是**物质**。

出生在空气里的身体一格水都没借过，于是连尸体都没有。

### 为什么不能直接给它一具普通尸体

`Corpse` 腐烂时**必定**变回 `Water`，因为"1 格尸体 = 1 格借来的水"是水位
守恒的地基。干尸体没有这份债务，让它留 `Corpse` 就是凭空造水（实测会多出
一万八千格）。

所以：

| | 借过水 | 没借过水 |
|---|---|---|
| 死后留下 | `Corpse`（带能量） | **`Remains`**（不带能量） |
| 腐烂 | → `Water`（还债） | 不烂（碎屑永远稳定） |
| 谁吃 | 嘴 | 嘴（`eat_remains`） |

`Remains` 是粉末，所以半空里死的会掉到地上堆起来。它也是 `eat_remains` 的
食物——**陆地有机质的入口**就在这一行。

## 变异率：两个数该往相反方向调

| | 基因数 | 每胎改几个 | 该怎么调 |
|---|---|---|---|
| 行为（权重） | 370 | 18.5（5%） | **改少** |
| 形态（段树） | 几十 | 2 | **改多** |

**权重为什么要改少**：一次改 18.5 个坐标，子代和亲代的适应度几乎无关，
选择就没有东西可筛。370 维里那不是爬坡，是随机游走——这正是"进化看着很随机"
的直接来源。降到 2%（每胎 7.4 个）。

**形态为什么要改多**：段树只有几十个基因，每个算子又只动一个段 / 一条边界。
2 个算子意味着一条谱系几十代才攒够结构变化，8000 tick 里分节能出现、
附肢几乎不出现。提到 6 个。

实测（512² · 8000 tick · 三个种子）：

| | 2 / 5% | **6 / 2%** |
|---|---|---|
| 体型众数 | 6 / 7 / 8 | **11 / 6 / 14** |
| 体长上限 | 14 / 16 / 24 | **24 / 24 / 24** |
| 动物数 | 645 / 320 / 340 | 251 / 539 / 143 |
| 物种数 | 137 / 126 / 115 | 113 / 136 / 85 |

**体型是明确的赢家**，代价是种群约降三成（更大的身体更贵）。

顺带一个结论：`MAX_BODY_CELLS = 24` 从此**真的成了天花板**。之前体型众数是
6–8、没人碰 24；现在三个种子的上限都顶到它。

## 没有鞭毛就一步也走不了

工坊里拼一株"下面是根、上面是生产者"的植物放在岸上，它看起来在正常获取
能量，能量却一直往下掉，然后饿死。

根因是一行：

```rust
// 旧代码
(1 + movers / 2).min(MAX_STEPS)     // ← 0 个鞭毛也是 1
```

**`speed()` 的下限是 1**，所以任何身体每 tick 都能走一格——哪怕一根鞭毛
都没有。而手工基因组给了 `OUT_RIGHT = 0.7` 的巡航偏置，于是那株"植物"
一直在往右爬。岸上每步 ×4，8 质量的身体每 tick 付 **32 点**，而它光合
只挣 ~45、维持 36。

实测（6 生产者 + 2 根，600 tick）：

| | 结果 |
|---|---|
| 原样 | 能量 1000 → 0，**死** |
| 把巡航偏置清零 | 能量 **2764/2800**，活着 |

**同一具身体，唯一的差别是"走不走"。**

改成「0 鞭毛 = 0 步」之后，人口从 482 涨到 **1017**——不是崩溃，是
**换了一个生态位**：一格或两格的生产者从此能活，而它们本来最便宜。
体型众数从 20 掉到 5/5/2，物种数翻倍。

## 工坊拼的身体现在能遗传了

`place_body` 原来只把玩家拼的格子写进 `Organism::cells`，而**基因组里那个
`body` 还是默认的一格**。于是亲代是 8 格的植物，子代长出来是**一格**——
没有根、没有生产者，落在岸上几 tick 就死。而画面上看起来完全正常：
它确实出生了。

现在拼出来的身体会写进基因组（`Body::from_cells`），"我拼的什么，
子代就长什么"（再叠上变异）。

## 繁殖门：改对了判据，改错了地方

`fits` 里那句"子代整具身体都在水下"把陆地永久封死了。实测一株内陆植物
能量攒到 **2764/2800**（门槛 1072），出生 **0**。

于是我把它换成一条**物理**判据：

```text
够得着水（至少一列在水下）  或  脚下是实体材质
```

刻意不提"根"——根只是"够得着水"的一种实现，以后动物上岸没有根，判据就
得再改一次。`is_solid()` 也不算别的生物，否则有一条"叠罗汉上天"。

**单元测试全绿，内陆植物真的能生了（出生 4~15 次）。然后生态炸了。**

第一次的解释是"陆地尸体在原地烂成水 → 水被身体托在空中 → 悬空水体里能出生"。
**听起来完全合理，而它是错的。**

## 加了两个仪器，当场否掉那个解释

| 数 | 含义 |
|---|---|
| `water_moved` | 累计有多少格湿细胞在**海平面以上**死亡（尸体还水的流量） |
| `water_above` | 现在有多少格水在**海平面以上**（存量） |

| | 门关着 | 门开着 |
|---|---|---|
| `water_moved` | **0** | **0** |
| `water_above` | 8 | **8420** |
| 悬空个体（其中挨着水） | 0 | 635（603） |

**尸体一滴水都没还**（流量 0），可海平面以上的水涨到了 8420 格。

## 真正的病根：身体是个水泵

```rust
world.swap(ox, oy, x, y);   // 身体挪进目标格，目标格里的东西换到刚让出的位置
```

**身体往下一格，那一格的水就被换到它刚让出的位置——身体往下游 = 水被顶上去。**
而水绕不过身体（被占的格算墙），顶上去的水回不来。**密集的表层生命就是一个
水泵**，而繁殖门一开，表层就密了。

所以顺序反了：**这道门要放宽，先得让"水能绕过身体流动"**——那是材质层的
事，不是生命层判据的事。

**教训：第一次的结论是错的，因为缺一个仪器。** 有了 `water_moved` 之后，
那个看起来很合理的假设当场被否掉。

顺带修了一个测量 bug：`sea_level` 原来是"最上面那格水的众数"、每次重算，
而它会随水面搅动漂一格——一漂就把整个表层算成"水面以上"，量出 0 → 663 的
假增长。**基准必须是常数。**

## 顺便：泡在水里 ≠ 浮得住

`apply_gravity` 原来只要 `touches_water` 就跳过重力，于是**一团"水 + 身体"
能互相托住**——身体挡着水不让它落，水又托着身体不让它掉。

现在多问一句：**最下面那格的正下方是空位吗？** 是空位就是"吊着"，重力接管。
只看一格就够了——整团会自己塌：最低那块掉下去之后上面的水跟着落，
上面那块又有水可浮了。三种子动物数改前改后完全一样（1017/453/1186），
这条在正常生态里是惰性的。

## 画上去的碎屑为什么吃不到

把一具全身是嘴的生物埋进自己画的碎屑堆里，它饿死。

根因是**一个字段**：`world.set` 会把 `flags` 清零，而 `flags` 正是残骸的
能量（`eat_remains` 读它）。所以画笔画的碎屑和尸体是**一格 0 能量的东西**
——能吃，但吃了等于没吃。

更隐蔽的是：`LifeSim::new` 里有一段"给所有 `flags == 0` 的残骸补 25 点"，
但它**只在开世界那一刻跑一次**。于是"开局前就画好的"能吃、"运行中画的"
不能吃，而这两件事在画面上完全一样。

现在落笔之后会调 `LifeSim::adopt_organics`：补 25 点，**并且记进
`ledger.injected`**（那 25 点是新进世界的，不记账的话 `audit()` 会报漏）。
只补 `flags == 0` 的，所以反复涂同一片不会一直加能量。

## 按住画笔 = 一直画

落笔原来只跟着 `CursorMoved` 走：**手一停，笔就停**。

而在任何画图软件里"按住"都是"持续"。更实际的是：**水会流走、沙会塌**，
所以同一格反复盖不是空转，它是"补上流走的那部分"——也就是"笔尖一直
在出水"。没有这一条，想画一条河只能来回蹭。

现在按住时每 50 ms 落一次笔（20 Hz）。不用每帧：60 Hz 下一个半径 5 的
笔刷每秒能盖四千多格，两秒就把世界填满。

## 尸体烂成水：设计，但有个代价

规则是**尸体烂掉之后永远变回水，不看它现在在哪儿**。理由：每一格尸体都
对应一格借来的水（出生时从世界里拿走的那一格）。如果按"现在泡不泡在
水里"决定，一条贴着水面出生的鱼死后，尸体在水面那一行、判定为"干的"，
那一格水就永久消失了——实测水位会在几百 tick 内悄悄少几格。

代价是**水会出现在尸体死的地方**：一具死在内陆的尸体会烂出一格水然后
落下来。这不是 bug，是体积守恒本身。

实测（4 格尸体）：

| 尸体来源 | 烂掉之后的水位 |
|---|---|
| 自然死亡（借过水） | **±0** |
| 画笔画的（没借过水） | **+4** |

第二行是"画笔即外部物质源"的直接后果——你能画水，也能画"将要变成水的
有机物"。它不算守恒 bug，但它意味着**画尸体等于预先存一格水**。

## 气（Gas）现在没有用

`worldgen` 会在浅海海床下撒 2×2 的气泡（512² 里 200 格），物理也是对的：
最轻、会上升、可被水挤开、可燃。

但实测它的**全部**行为是：

| tick | 气格数 | 最高 y |
|---|---|---|
| 0 | 200 | 131（水面线 128） |
| 100 | 200 | 29 |
| 500 | 200 | **0** |
| 2000 | 200 | 0 |

**500 tick 内全部升到世界顶部，然后永远停在那儿。** 不消散、不参与反应
（除了火），而生命层里它只出现在"这格能不能通过"的判定里——**没有任何
生物读它**。

所以它现在是"一个会飘到天上然后一直躺着的燃料"。三个方向都还没做：
到顶逸散（一行代码）、改成燃烧的产物（要先把"烟"和"燃料"拆成两种材质）、
或者就留着手动点火用。

## 湿度是一张二维的图，而且能看

### 旧模型抹掉了"高度"

v0.41 的湿度是**每列一个数**：`255 × (1 − 离岸列数 / 200)`。512² 的世界
只要 512 字节，很省——但它把"高度"整个抹掉了。

具体到一格：一株长在离海 3 格、但比海面高 40 格的悬崖上的植物，按列算
是"满水"，而它实际上够不到任何水。反过来，海底以下两百格的沉积物也是
"满水"，因为那一列有水。

**"离水多远"本来是一个二维的量，按列算等于只算了一个分量。**

### 新判据只有一条

```text
湿度(p) = 255 × (1 − 到最近水格的距离 / 200)
```

于是海岸湿、内陆干；悬崖根湿、崖顶干；内陆湖有一圈湿地；海底以下全是满值。
**这些都不是新规则，是同一条规则的二维结果**——这正是换模型最想买到的
东西：不用为"高地"、"内陆"、"绿洲"各写一条。

算法是两遍 chamfer 距离变换（权重 3/4，误差 6%，只用整数加法），横向环绕。

### 为什么是粗格 4×4

因为它要**每 tick 重算**：逐格算 512² 要几毫秒，50 tick/帧就是几百毫秒；
粗格（128×128）实测 **0.45 ms**（一个 tick 是 4.0 ms，所以是 11% 的固定开销）。
而且场纹理（光、温度）本来就是 4×4 的，
湿度用同一套格子之后可以直接灌进去，连平均都不用算。

代价是湿度按 4 格台阶走，而根的回充档位是 40 点一档——玩法上看不出来。

### "每 tick 重算"顺手删掉了两个坑

- **画笔改的材质不算**：挖一个湖，根吸不到那几格水。
- **存档得存它**：否则"存档那一刻的湿度"和"读档时重算的"可能差一点点，
  而两条鱼会因此游向不同的方向。

每 tick 重算之后这两件事同时消失：**湿度永远等于当前世界的函数**。
画笔那条仍然要显式刷（暂停时 `step` 不走），所以留了 `refresh_moisture`。

### 新滤镜：湿度

第五个视图。和温度、光照不同，它**看材质**：水画满值，石头/沙按湿度画，
天空不画——不遮的话一整根柱子连天空都染成一个颜色，像糊了一层膜。

```
干土 #9A7F5E → 深青 #2F6F8F → 亮青 #7FD8FF → 近白 #E8FBFF
```

暖色那一段拉到 0.35：内陆一大片都该是土色，只有靠水那一小片转蓝。

**这个视图的直接用途是验证上一轮那张"能走多远"的表**：植物活到哪一列，
图上就是色带在哪一列断掉。

## 悬停读数：从"三处手写"改成"一张探针表"

读数原来分在三处：`CellInfo` 定义字段、主循环填值、面板排版成几行字。
加一项要改三处，而且**漏掉一处不会编译报错**——它只是不显示。

现在只有一处：`core/src/probe.rs` 的 `cell_probes()`，返回一张分组的探针表。
界面只负责把 `Value` 排版成字符串，**它不认识任何一个具体的量**。

```
格    坐标 271, 168     深度 -19 格     材质 空
场    光照 0.71         温度 22 °C       湿度 96/255
生物  #4821 · 10 格 · 代 37
      细胞 叶绿体 ×2 + 线粒体 + 根
      能量 612/1400     生物量 90/500    含水量 255/255
```

**说清楚"自动"的边界**：这里买到的是**"只写一处"**，不是**"不用写"**。
没有人能自动知道哪个数值得显示（真正的反射式转储会把 398 个权重一起
倒出来）。但那一行加完就一定会显示，界面不可能忘、也不可能显示错位。

两条约定：值里**带单位而不预拼字符串**（界面要按数值本身取色，先拼成
`"20 °C"` 再解析回来是最常见的坏味道）；整组都是 `Missing` 时**不画组标题**。

## Esc 不再退出

原来：正在放置身体 → 取消放置；否则 → 直接退出程序。

问题在**顺序**上——"放完一只生物 → 想取消 → 按 Esc"是一个连续动作，
手一抖按第二下，程序就没了。

现在 Esc 只负责**打开确认框**，而框里只有两个按钮，**Esc 永远只取消、
永远不确认**（一旦 Esc 能确认，防误触就白做了）。退出只能点按钮。

窗口右上角的 X **不接**这个确认：点 X 是明确的、只可能有一个意思的动作，
加确认不会减少误触，只会让"关不掉"变成新问题。这个框服务的是**键盘**。

## 植物怎么上岸：含水量 + 根

光合的判据一直是"**身体所在的粗格里有水**"。那条判据对叶绿体本身是对的
——它确实要水才能工作。但它有一个副作用：

> **整株植物被钉在水里。** 只要身体离开水面，产量立刻归零。

于是"上岸"不是一件难事，是一件**不可能**的事。

### 拆成两层

```
含水量 hydration（0..=255，每 tick 更新）
   根贴着水 或 身体泡在水里 → 回满
   否则                      → 掉 1/tick

光合 = 产能 × 光照 × 温度 × damp × (hydration / 255)
                                 ↑
                      damp = max(粗格水占比, 根贴着水 ? 0.35 : 0)
```

- **`hydration` 是"带在身上的水"**：出水之后还能撑 255 tick（1× 约 4 秒），
  然后停摆。退潮的水洼能活一阵，但撑不过旱季。
- **根细胞器**（`1 << 12`，维持 1/tick）是"补水的能力"：只要**某一格根**的四邻
  有水，含水量就回满。判据是"根够得着水"，不是"身体泡在水里"——这就是根和
  浮在水面的区别。

### 岸上故意比水里差

`LAND_DAMP = 0.35` 是根能提供的地板。岸上光更强（没有水的衰减），两者相乘
之后大约等于水里的一半——**这是刻意的**。

如果岸上比水里划算，第一株长出根的植物会立刻铺满陆地。v0.23 的海草已经演过
一遍：481 株、把光吃光、鱼一条不剩。**陆地说到底该是"能活但更苦"的地方。**

### 还没发生的事

8000 tick 里**没有长出带根的植物**。机制在那里，但没有任何选择压力把突变推向
它——手工基因组没有"往岸边去"的倾向，而岸上本来也没有收益。
这一条只能由"先在工坊里手工种一株"来验证，不能指望它自己出现。

## 根：从"有没有"到"多厚"

上一轮给植物加了根，然后 8000 tick 里**一株带根的植物都没出现**。

原因不在根，在它前面的那个数：

```rust
pub const LAND_DAMP: f32 = 0.35;
if damp < LAND_DAMP && root_is_wet(org) { damp = LAND_DAMP; }
```

一格根和十格根产得**一模一样多**。根是一个**开关**，不是一个可以被投资的东西，
于是突变没有任何理由往"多长根"走。

换成斜坡：

| 根格数 | 1 | 3 | 5 | ≥6 |
|---|---|---|---|---|
| `damp` | 0.28 | 0.44 | 0.60 | 0.60 |

- **起点 0.20 比原来的 0.35 低**，因为那个 0.35 当时是**上限**（一格根就拿到全部），
  现在它只是第一格。一格根反而变差了——这是对的，它本来就该是"刚够活着"。
- **上限 0.60**：岸上光更强，`0.6 × 强光 ≈ 水里满产`。再往上抬，第一株厚根系
  植物会铺满陆地（v0.23 海草 481 株的重演）。
- **用 `max` 不用赋值**：半泡在水里的身体不该被根系"拉低"到岸上的地板。

**买到的是梯度，没买到的是"发生"。** 8000 tick 里仍然没有自发的带根植物——
梯度只是必要条件。根要真被长出来，还得有"岸上有东西可拿"，那是下一个决定。

## 食腐早就在发生，我们只是没量过

上一轮（生物量账户）之后我写过一句话：

> "出现只吃尸体也能活的谱系" —— **未观察到**。

这一轮加了计数器（`LifeStats::scavenged`，只数"吃掉的是尸体"而不是碎屑），
一跑就发现这句话是错的：

| | 8000 tick 吃掉的尸体格数 |
|---|---|
| seed 11 | **81,834** |
| seed 2026 | **111,934** |
| seed 7 | **72,255** |

约 **10–14 格尸体/tick**。食腐**一直在发生**，只是之前没有仪器。

而"尸体存量"这个替代指标根本不能用：它同时受死亡率、腐烂速度、材质模拟影响，
从 1515 掉到 897 说明不了是谁干的。

### 所以这一轮真正加的是什么

一条**独立的尸体嗅觉射线**（`INPUTS` 22 → 24）：复用不了 `IN_FOOD_DIR_*`，因为
那一路遇到**第一个**食物就停，而海里第一个食物几乎总是藻——"最近的尸体"
永远被盖住，这一路会恒为 0。

判据也故意不同：**活体和碎屑不挡**（腐烂的化学信号溶在水里），只有石头挡。
尸体最多的地方恰好是鱼群脚下，而鱼群会把食物射线挡死。

A/B（把这两路输入硬写成 0）之后：通道开 8.2/11.2/7.2 万，通道关 8.0/7.9/6.4 万。
**方向一致（3/3 种子，平均 +19%），但幅度在混沌范围内。** 只能说"有帮助"，
不能说"它让食腐成立"。

### 一条方法论

**`没观察到` 有两种：一种是没有现象，一种是没有仪器。**

分不清这两者时，"验收未达成"这句话是危险的——它会让你去修一个没坏的东西。
这一轮如果没加那个计数器，我大概会接着去"修食腐"，而它从来就没坏。

## 细胞颜色 = 细胞器的颜色混出来的

以前一格的颜色由它的**类型**决定（7 种枚举之一）。问题是类型是有损的：
`叶绿体 + 气囊` 的代表类型是 `Producer`，于是它和纯生产者画出来**一模一样**
——而"漂浮的藻垫"和"普通水藻"是两种活法。

现在颜色是**算出来的**：

```text
颜色 = (各细胞器基色的加权平均) × (1 − 0.10 × (份数 − 1))
权重：叶绿体 / 鞭毛 / 刺 按等级算（2 级 = 2 份），其余开关各 1 份
线粒体：不参与混色，只画一个白点
```

| 组合 | 颜色 |
|---|---|
| 叶绿体 | 绿 `#56C860` |
| 叶绿体 2 级 | 浓绿（暗 10%） |
| 叶绿体 + 气囊 | 薄荷 `#A2D9B8` |
| 叶绿体 + 装甲 | 灰绿 `#86BE9E` |
| 嘴 | 鲑红 `#E9917D` |
| 根 | 棕褐 `#AD917B` |

**没有人写"硬壳藻是灰绿的"这条规则**，是混色自己算出来的。

### 为什么线粒体不参与

它几乎每格都有（"所有主动功能的前提"），按一份掺进去会把所有颜色拉白：
装甲 `#B4C4D0`、根 `#C0B0A2`、气囊 `#D5E2EE`——三个分不出来。
所以它只做标记：着色器在那一格里点一个白点。

### 顺带

纹理里存的不再是"类型编号"，而是**细胞器位掩码**（13 位）。
位宽是这样分的：`1 位标志 + 18 位编号 + 13 位细胞器`。编号从 23 位缩到 18 位
（26 万个，一个会话用不完），换来的是"组合自己就是颜色"。

## 检视：点一格，看它带哪些细胞器

缩略图现在能点。点中的格子显示它的细胞器清单（叶绿体 1 级 / 气囊 / 线粒体），
再点一次取消。

「细胞构成」也改成了**按细胞器统计**：一旦一格可以是"叶绿体 + 气囊"，
按类型分桶就不再可加——那 13 格里到底几格是生产者？取决于你数哪一列。

### 形态发生（不是发育）

面板里多了一段「形态发生」：段树、逐层展开的格数、梯度带。

```
主干 4 格 ×3 镜像
  └ 段 2 格 ×2 叶绿体
逐层：1 → 4 → 8 格
带1 沿 0.00–0.35 +嘴
```

**但它不是"发育"。** 身体在出生那一刻就长完了，之后只死不长——
所以这里画的是"基因组 → 身体"那一次计算的过程，不是一个细胞分裂成一群。
面板最后一行把这句写死了，免得误读。

## 根能从土里吸水了

以前根只认"四邻是 `Water`"，于是根是个**水边开关**：内陆一格水都没有，
根扎得再好也活不了，植物永远上不了岸。

现在多一条路：根四邻是石头或沙 → 按**那一列的土壤湿度**吸。湿度是
"离最近的含水列有多远"的线性函数：

```text
湿度(d) = 255 × (1 − d / 200)
```

于是海岸湿、内陆干，**"能走多远"第一次有了空间上的答案**。

### 实测：多干就活不下去

受控平台（左边是海，右边一整块平地），每档距离放一株，跑 3000 tick：

| 体型 | 维持 | 最远可活 | 那一列的湿度 |
|---|---|---|---|
| 4 产 + 2 根 | 22 | **40 列** | 203 |
| 6 产 + 3 根 | 33 | **70 列** | 164 |
| 8 产 + 4 根 | 44 | **90 列** | 139 |
| 10 产 + 6 根 | 56 | **100 列** | 126 |

**根系越发达走得越远。** 不是"能不能上岸"，是"能走多远"——而这条
正好接上上一轮的 `land_damp(根格数)`：根决定抽多快，土壤决定抽得到多少。

### 挖出两个只在 release 下出现的 bug

**一、`u8` 溢出。** 回充写成 `(hydration + refill).min(255)`，满水时
`255 + 5` 在 release 下回绕成 **4**——"水最多的地方植物最渴"。
debug 下它直接 panic，而单元测试跑 debug，所以只有生态测量看得到。
改成 `saturating_add`。

**二、产量逐格截断。** `(...) as u32 * producers` 先把单格产量截成整数再乘格数：
单格 4.72 截成 4，一条 6 格的身体每 tick 白丢 15%。在岸上（产能只有水里
三分之一）这是生死差别——同一株植物，逐格截断时离岸 40 列饿死，
整具截断时活到 50 列。

## 一个石头做的世界

有人连着说了两轮"石太多、水太少"。量了一下：

**水面线以下六成是基岩。** 海是贴在表面的一层膜。

### 三个数一起改，缺一个都不够

| 常量 | 旧 | 新 | 为什么 |
|---|---|---|---|
| 陆地目标 | 50% | **35%** | 陆地是**实心**的，一列陆地从地表到世界底全是石头——"一半陆地"等于"世界一半是石头" |

## 点一下就闪退的"大世界"

预设"大 768×728"点下去直接 panic：

```
index out of bounds: the len is 559104 but the index is 559104
```

559104 = 728 × 768，也就是**第 728 行的第一格**——世界末尾的下一个位置。

渲染层的分块循环按 `0..CHUNK_SIZE`（64）走，而 `chunk_rows` 是 `div_ceil`：
最后一块覆盖 704..768，世界却只有 728 行。**只要宽或高不是 64 的倍数就会越界**
——滑块的取值范围里绝大多数尺寸都踩这条，只是 256 / 512 恰好是 64 的倍数。

修两层：循环用 `chunk_w(cx)` / `chunk_h(cy)` 夹到实际尺寸；
`write_chunk` 的 `extent` 用实际宽高——**`bytes_per_row` 是缓冲区布局
（必须 256 的倍数），`extent` 才是"拷多少"，两者不能混用**。

### 顺带发现：那个上限连默认世界都容不下

修完之后新加的 `presets_are_within_the_limits` 报"标准 512×512 的高 512 越界"
——`MAX_HEIGHT` 原来是 **450**，比默认值还小。

**一个上限如果连默认值都容不下，它就不是上限，是笔误。**

而且预设走的是另一条赋值路径（直接写 `state.world.width`），不经过滑块的
`clamp`——所以"尺寸合法"必须在两处都成立。现在两处都夹，并且有测试钉住。

## 海太浅了：水占世界 2.4%

有一轮统计了一下世界的材质占比，结果很难看：

| | 512² · 种子 11 |
|---|---|
| 石头 | **72.7%** |
| 天空 | 22.9% |
| 水 | **2.4%** |
| 海床基准线以下的固体 | **60.2%** |

**世界下面五分之三是纯石头**，而没有任何生物能破坏地形或钻进去——一块彻底
的死区。海只有 71 格深，而世界高 512。

### 根因：海深被"陆地不能顶出世界"绑住了

地形的高度场是一张噪声，归一化到 0..1 之后按分位数切海岸线，然后乘一个
比例尺 `scale`。`scale` 取三个约束的最小值，其中一个是"陆地不能顶出世界"
（`(waterline−2)/(1−cut)`，512² 里是 252）。**海侧被迫用同一个 `scale`。**

但海床深度本来受的是**另一个**约束——`水平跨度 × 坡度`。254 列的海 × 1.2
≈ 305 格，垂直空间本来够用。两个约束根本不该共用一个数。

### 改法：深度由"离岸多远"决定

```rust
// 陆侧照旧；海侧：深度正比于离岸距离，到上限封顶
let base = (SEA_SLOPE * shore_dist[x] as f32) as isize;
surface[x] = waterline + base.min(max_depth) + 细节噪声;
```

坡度上限 2 仍然成立——而且它本来就是为了**行走**，海床不需要更陡也不需要
更浅。海岸线两侧的导数分别是 ~1.0 和 1.2，所以不会重新长出 v0.30 那个折角。

### 还要一条大尺度倾斜

只改深度不够。fBm 的基频是 1.6，整张图只有一个半起伏；峰落在中间时，两边
各剩一条窄海——而深度现在按离岸距离算，**窄海就永远是浅的**。实测三个种子
的水占比是 14.9% / 4.9% / 7.4%，差三倍。

加一条线性斜坡（`TILT = 0.70`）之后，剖面必然是"一头高一头低"，海连成一片。
噪声仍然决定海岸线在哪、有几个海湾——**倾斜只决定"哪边是海"**。

### 结果

| | 之前 | 现在 |
|---|---|---|
| 最深 | y=199 | **y=403** |
| 水占世界 | 2.4% | **14.9%** |
| 石头 | 72.7% | 60.3% |
| 海床以下的死石头 | 60.2% | **20.9%** |

**水多了 6 倍，死区从 60% 降到 21%。** 剩下的石头主要是"陆地下面"——
那不可避免（地面必须是实的），也是将来的挖掘空间。

代价是浅海变少了：海深 276 格而阳光 180 格就衰减完，透光的海床只剩离岸
约 150 列。但总水量多了 6 倍，生物数反而从 798/321/1026 涨到 1617/1583/1088。

## 身体进光场

这条是"植物为什么能长高"的答案。

原来的决定是**生物本身不遮挡**——光场只认材质，这样它才是布局的纯函数。
代价是：**长高没有任何收益。** 自己挡自己只有损失，而挡住邻居才是植物长高
的唯一理由。

现在 `AirField::scan` 数每个粗格被生物占了几格，`sun_march` 按**覆盖度**给
下面的格打折：

```rust
let cover = self.body[i] as f32 / (AIR_CELL * AIR_CELL) as f32;
acc *= 1.0 - BODY_SHADE * cover;   // 在 light[i] = acc 之后
```

**顺序是有意的**：打折放在存完 `light[i]` 之后，所以生物拿到的仍然是"头顶
来的光"，它挡的是**下面**的格。反过来会让每一具身体都把自己压暗——那不是
竞争，是自杀。

### 为什么按覆盖度而不是"有没有生物"

粗格是 4×4。一条 4 格的鱼只占 25%，不该把下面整列变黑；而一片密实的藻席
或一丛海草能占满整格，那才是真遮挡。

**这个分辨率决定了"竞争"发生在个体之间还是群落之间。** 单株植物的影子只有
1/16，所以"高个子挡住矮个子"在单株层面几乎不发生，但成片的植被会。真实
生态里植物的光竞争本来也是成片发生的——所以刻意选了"群落级"。

### `0.2` 是量出来的

遮挡按粗行**连乘**，而鱼群聚在透光层，十几个粗行都压着鱼。

| `BODY_SHADE` | 动物数（三种子） | 物种数 |
|---|---|---|
| 0（关） | 1617 / 1583 / 1088 | 350 / 334 / 271 |
| **0.2** | **645 / 320 / 340** | 137 / 126 / 115 |
| 0.5 | 196 / 176 / 99 | 52 / 78 / 58 |

0.5 是**八倍**的崩塌：`0.81^10 ≈ 0.12`，整列水下直接黑掉。0.2 保住了生态，
而"密实的身体压暗下面"仍然成立。**这个数是"生态能承受的最大值"，不是
"物理上最像的值"。**

## 为什么身体长不大（一次被撤销的改动）

有一件事看起来显然：叶子是薄的，因为第二层晒不到光。于是"产能按暴露表面积算"
被写进了计划——每多一层压在自己头顶，产量打折。

实现、测量、**撤销**。三个系数 × 三个种子之后，它不成立。

| 指标 | 关闭 | 0.45 | 0.2 |
|---|---|---|---|
| 动物数（三个种子） | 798 / 321 / 1026 | 726 / 302 / 1338 | 438 / 272 / 969 |
| 体长上限 | 24 / 11 / 24 | 24 / 24 / 22 | **9 / 20 / 10** |
| 体型众数 | 5 / 6 / 6 | 4 / 6 / 6 | 6 / 2 / 6 |
| 扁平度（宽/高） | 2.30 / 4.81 / 1.88 | 1.73 / 3.39 / 2.23 | 2.06 / 2.81 / 2.22 |

### 三个原因

**一、前提就不成立。** 这条规则的依据是"24 格的身体活得比 14 格好，所以
体型只有一个方向、上限会成为天花板"。但那个测量问的是"**投放给定体型能不能
活**"，不是"**进化会去哪**"。真实生态的体型众数是 **4–6 格**——上限 24
从来没人碰到。

**二、收入与成本两边都线性，所以大小是中性的。**

```
收入 = 24 × 光 × 水占比 × 等效满产格数
成本 = 5 × 格数 + 移动
```

平铺的身体上两者都正比于格数。自遮挡只惩罚"堆叠"，不改变"大小"。
把系数压到 0.2 时它确实咬人了，但咬掉的是**大小**（上限 24 → 9），
不是形状——那不是"选出了更好的体型"，是"把大的都饿死了"。

**三、按列遮挡能被稀疏形状绕过。** 0.45 那一档最反直觉的结果是：
**扁平度在三个种子上全部下降**。因为一条对角线上的 24 格，每列只有一格，
完全不遮挡。所以"躲开遮挡"的最优解不是"变薄"，是"变稀"。

**判据的形状决定了优化器会找到什么。**

### 所以真正的杠杆是什么

真实植物长高是为了**挡住邻居**。而我们的光场明确不算生物——那是当初为了
让光场保持"材质的纯函数"而定下的。没有这一条，长高没有任何收益：

- 自己挡自己只有损失；
- 植物永远长不大；
- "高大 > 扁平"在物理上不可能出现。

下一步不是"自遮挡"，是**"身体进光场"**。它会推翻那个早先的决定，所以要
先问过再动手。

### 一个方法论：单种子对比在这里没有意义

同一个规则、只换种子，动物数是 **321 / 798 / 1026**——差三倍。
所以"改了之后从 798 掉到 726"这种话是不能说的。
`crates/core/tests/m7_probe.rs` 就是为此写的：三个种子 × 8000 tick，
一次打出动物 / 藻 / 物种 / 体长 / 众数 / 形状种数 / 扁平度。

## 追与逃

两路新输入：**最近的别的生物在哪边**（`IN_ORGANISM_DIR_X/Y`）。在它之前你只能
撞上才知道有别人，于是捕食全靠运气、猎物从不躲——那不是生态，是随机碰撞。

引擎只给通道，**怎么反应是基因的事**：

| 倾向 | 谁用 | 接线 |
|---|---|---|
| `Hunt` | 有杀手细胞的 | 靠近 |
| `Flee` | —— | 远离 |
| `Ignore` | 手工起点里的非捕食者 | 不接 |

**"逃"写好了、测过了，但手工起点不敢用。** 一旦猎物会躲，捕食者在三种尺度下
**全部灭绝**（512² 起步 24 / 120 条、128² 起步 20 条）——因为两者**速度一样**，
追的一方永远追不上。这不是"逃"写错了，是"逃"太有效了：它把捕食变成了需要
**技巧**的事，而手工基因组没有技巧。所以"逃"作为一条通道留给突变。

## 有牙的会咬

杀手细胞每 tick 从**邻格的别的生物**身上咬下一口能量。

**咬不咬不是网络输出。** 没有 `OUT_BITE`，也刻意不加——和"手工基因组不该被硬塞
觅食策略"是同一条：**有没有牙由体型决定**。杀手细胞自己就要付维持成本（3/tick，
和生产者一样贵），养不起就饿死，这已经是足够强的选择压力。

**能量是转移，不是注入。** 猎物少多少，捕食者就多多少（装不下的记进耗散）。
所以守恒断言依然成立，而捕食只改变能量的**分布**——那正是频率依赖选择的物理来源。

**装甲第一次有了用处。** 在此之前它只是"加重、不产出"的配重，纯粹是设计上的减分项。
现在每格装甲挡掉 8 点（一口 30 点）：

| 体型 | 装甲 | 实际挨咬 |
|---|---|---|
| 银鱼 / 蠕虫 | 0 | 30 |
| 水母 | 2 | 14 |
| 叶背鱼 | 3 | 6 |

**软的身体成为猎物**，于是"要不要长装甲"第一次是个真问题。

### 捕食者需要猎物密度

这不是 bug，是生态：

| 世界 | 起步 | 8000 tick | 16000 tick |
|---|---|---|---|
| 512² | 24 条 | 杀手 8 枚 | **0 枚（全灭）** |
| 512² | 120 条 | 杀手 14 枚 | **14 枚（稳定）** |
| 128² | 20 条 | 杀手 6 枚 | **4 枚（振荡）** |

128² 那组 `2 → 6 → 2 → 4` 是一个真实的捕食者—猎物振荡。512² 那组说明：
**猎物太稀时捕食者会先饿死**——自然界也成立（捕食者需要最低猎物密度）。
所以「世界」窗口新建时默认投放 8 条，而 `--fish` 建议给到 16 以上——
玩家得能跨过那道门槛。（早先有个"按 L 一次放 16 条"的快捷键，v0.25 删掉了：
投放这件事已经收进「世界」窗口和生物工坊。）

> 观测上有个坑：捕食者灭绝之后，**"生物数""细胞数""能量账"三项全都正常**。
> 所以加了 `LifeStats::killers`——它归零就说明少了一整个营养级，
> 而那从别的指标上完全看不出来。

## 界面

骨架用 **egui**，关键控件**自绘**。

**结构照 ALIEN**：左边工具、中间视口、右边检查器、下面控制台。
那三个分区不是随便分的——它们对应"操作 / 观察 / 追溯"三种动作。

**皮肤照 The Powder Toy**：纯黑面板、1px 实线边框、悬停提亮、
**按下整体反色**。没有圆角、没有阴影、没有渐变。世界里的每一格像素
都是有意义的，界面不该有装饰性的柔和边缘。

```
┌──────────────────────────────────────────────────────────────┐
│ ▣ VIVARIUM   tick 28431  ● 运行  1× 5× 50× MAX │ 303fps 1.3ms│
├────┬────────────────────────────────────────┬────────────────┤
│ ✏  │                                        │ 选中 #42       │
│ ▤  │                                        │ ▛▀▀▜ 缩略图    │
│ ⬚  │      世界（wgpu 直接画，                │ 能量 312/3500  │
│ ⚲  │       egui 不参与）                     │ ╱╲╱╲ 走势      │
│ 🔍 │                                        │ ‖‖▁‖‖ 17 路输入 │
│    │                                        │ ▬▬▬▬ 6 路决策   │
│    │                                        │ ▦▦▦ 权重矩阵   │
├────┴────────────────────────────────────────┴────────────────┤
│ 材质 ▉▉▉▉▉▉▉▉   细胞 ▉▉▉▉▉▉▉          笔刷 ▬▬●▬▬  2 格    │
├──────────────────────────────────────────────────────────────┤
│  28431  ··· 投放 24 条                                       │
│  32000  !  捕食者降到 1 枚——猎物密度可能不够                 │

```

左栏五个工具：**画笔 / 橡皮 / 填充 / 取样 / 检查**（B / E / F / I / Q）。
调色板下半排的细胞色块是**图例**，点不动——细胞的颜色是一套语言，
界面必须把它写出来，但"往世界里单独放一格细胞"不该做成画笔
（细胞属于某个有机体，单独一格是个没有身体的怪东西）。

### 为什么自绘

egui 默认是圆角、内阴影、悬停渐变的"现代桌面"风格。用它的控件再改
`Visuals` 达不到 TPT 那种机械感：圆角半径、内边距、文字基线散在十几个
字段里，改到最后是在别人的设计里打补丁。

自绘的判据可以写成一句话：

> 默认 = 1px 边框 + 透明底；悬停 = 边框变亮；按下 = 整体反色。

自绘的只是**外观**，交互模型照搬 egui（`Sense::click` / `drag`）——
触摸、键盘焦点、无障碍这些没人想重写。

| 控件 | 位置 |
|---|---|
| `flat_button` | 顶栏的速度档、单步 |
| `icon_button` | 左栏的七个工具（图标是 `Painter` 画的几何形状） |
| `swatch` | 底部材质 / 细胞调色板 |
| `value_slider` | 笔刷大小 |
| `stat_row` / `section` / `sparkline` | 右侧检查器 |

### 三条硬约束

1. **不依赖 wgpu / winit。** 和"`vivarium-render` 不依赖 winit"是同一条。
   分开之后界面能在**没有显卡的机器上**跑布局测试——egui 的 tessellate
   是纯 CPU 的。`crates/ui` 的两条测试就是这么跑的。
2. **不认识模拟。** 输入是 `Snapshot`（只读快照），输出是 `Command`
   （要主循环做的事）。界面里没有 `&mut World`。
3. **不自带配色。** 色块颜色取自 `vivarium_core::palette`——界面上的绿
   必须就是世界里那个绿，否则"点这个会画出什么"要重新学一遍。

### 想看一眼界面

`png` 只是 dev-dependency，不进发布产物，所以截图是个测试：

```bash
cargo test -p vivarium-game --test ui_preview -- --nocapture
# → target/ui-preview.png
```

它同时是一组**像素断言**：五块面板的底色、左栏边界的精确位置、
中央没有被面板盖住、每种材质和细胞的色块都真的画出来了、
检查器里确实有文字。这个模型看不了图，所以"看一眼"换成了这些判据。

### 中文字体

egui 内置字体不含 CJK。不装的话界面上的中文全是方块——那不是"不好看"，
是整个界面不可读。但一个中文字体 10~20 MB，而 `dist/vivarium.exe` 只有
6.8 MB，打进去体积翻三倍。

所以启动时按 `雅黑 → 黑体 → 宋体` 的顺序找系统字体，找不到就在横幅里
明说"中文会显示成方块"。

### 现在能做什么

**改世界**：七个工具——**画**（`B`）、**生物橡皮**（`X`）、**物质橡皮**（`E`）、
**填充**（`F`，四邻域，封顶 6 万格）、**取样**（`I`）、**检视**（`Q`）、**光源**（`P`）。
左键落笔，**右键或中键拖拽平移**，滚轮**以指针为中心**缩放。
笔刷半径有预览圈——多涂三格水和少涂三格在画面上都不明显，只有能量账知道。

矩形和直线被去掉了：它们需要"按下 → 拖动 → 松开"三段式，而拖拽现在是平移视野，
两个功能抢同一个手势一定有一方误触。

**两个橡皮删的是两种东西。** 生物橡皮删掉笔刷圈内的**整个有机体**——半条鱼
不是生物，删一半只会留下一个能量为正、细胞不足、行为网络还在跑的残躯，
它既不繁殖也死不掉，是世界里最难看的垃圾。物质橡皮只擦材质，不碰生物。

**删生物走的是编辑路径，不是死亡路径**：不留尸体、不记能量账、把借走的那格水
还回去。三条都必须——不还水的话玩家反复擦能把海擦干；记 dissipated 的话，
"玩家擦掉"会被记成"能量耗散"，账本开始说谎。

**光源点一下开、再点一下关。** 不另设"删除光源"的工具，少一个按钮，
而且符合"点一下开关"的直觉。

**画笔不涂生物。** 一格要么是材质要么是细胞，硬涂上去会让占格表和材质打架
（那条鱼还占着这格，而格子已经变成石头），症状是"鱼突然不动了"。

**放生物是连续的**：在工坊里选中体型之后按一下，就可以一直点着放，
按 `ESC` 停止。`ESC` 只有在没有在放东西的时候才是"退出"——玩家按它十次，
有九次是想取消点什么。

**看世界**：速度档、暂停 / 单步、重铺地形、缩放回正，
外加**四个滤镜**（材质 / 温度 / 光照 / 物种，`V` 键循环，顶栏上直接写着 `视图 V`）。
切滤镜**不弹任何提示**——顶栏在最上面，任何浮层都只能往下压在世界顶上，
而那时候你正要看世界。

指针旁边那个读数框在靠近顶栏时会**翻到指针下面**（而不是被夹在顶上），
所以它不会盖住你刚切完滤镜要看的那一片。

**底部那排细胞是图例，不是画笔。** 它回答"世界里那个橙红色的方块是什么"，
点不动（边框更暗、悬停也不发亮）；悬停时它的说明会出现在下面那行描述里。
往世界里放细胞没有意义——细胞属于某个有机体，单独丢一格进去是一个没有身体的
怪东西。投放请在「世界」窗口里新建时勾上初始生命，或者在生物工坊里画一副。

**看一格**：指针停在世界里，旁边浮出五行读数——坐标与深度、物种（或材质）、
能量 / 生产者数（或材质说明）、光照、温度。靠近屏幕右边时框自动翻到左边，
正在落笔时不显示（不然它正好挡在笔刷圈上）。

深度是**向上数出来的**：从这一格往上扫到第一个非水格，数到的行数。
这比"y 减去水位线"准，因为水位在世界里不是一条直线（有岛、有被身体占住的格）。

**看一个个体**（用「检视」工具点它）：身体缩略图、能量 / 上限、年龄、
维持与移动成本、速度、嗅觉、能量走势、细胞构成条，以及——

- **17 路感知**画成一条竖带（哪几路在动一眼可见，悬停看数值）；
- **6 路决策**画成条，外加"本 tick 在做什么"；
- **行为网络的直连权重矩阵**（17 行 × 6 列热力图，绿正红负）。

最后那一条是重点：只给"能量 312、速度 1"回答不了"它为什么这么动"；
给出"光照 0.70 → 上（−3.0）"和"食物 y +0.55 → 下（+1.5）"之后，
"它为什么在这个深度"就变成一道自己能算的题。

## 快速开始

需要 Rust stable 与 MSVC 工具链（Windows）。

```bash
# 图形前端：开窗，看像素画面
cargo run --release -p vivarium-game

# 没有 GPU 或没有显示器时，在终端里跑同一套内核
cargo run -p vivarium-game -- --ascii

# headless 模拟并打印 ASCII 视图
cargo run -p vivarium-sim -- --width 256 --height 256 --ticks 1000 --ascii

# 在最高的岛顶点一把火，每 500 tick 报一次进度
cargo run --release -p vivarium-sim -- --ticks 3000 --ignite 40 --report-every 500

# 在水面附近放 20 条鱼，看它们游、吃、生、死
cargo run --release -p vivarium-sim -- --ticks 3000 --fish 20 --report-every 500

# 指定材质层的并行工人数（默认 0 = 自动）
cargo run --release -p vivarium-sim -- --ticks 1000 --threads 4

# 对照实验：关掉藻，看它到底改变了什么
cargo run --release -p vivarium-sim -- --ticks 16000 --fish 24 --no-algae

# 形态发生：身体由基因组**长出来**，而不是用手工体型表
cargo run --release -p vivarium-sim -- --ticks 16000 --fish 24 --morph

# 查看全部参数
cargo run -p vivarium-sim -- --help

# 测试
cargo test --workspace
```

窗口里的操作：

| 输入 | 作用 |
|---|---|
| **左键** | 落笔（工具决定画 / 擦生物 / 擦材质 / 填 / 吸 / 看 / 放灯） |
| **W** | 打开生物工坊（网格上画身体） |
| **G** | 打开「世界」窗口（新建 / 保存 / 读取） |
| **右键或中键拖拽** | 平移视野 |
| **滚轮** | 以指针为中心缩放 |
| `B` / `X` / `E` / `F` / `I` / `Q` / `P` | 画笔 / 生物橡皮 / 物质橡皮 / 填充 / 取样 / 检视 / 光源 |
| `V` | 循环切换滤镜（材质 → 温度 → 光照 → 物种） |
| `空格` | 暂停 / 继续 |
| `1` / `2` / `3` / `4` | 速度 1× / 5× / 50× / 最大 |
| 方向键 / `0` | 平移 / 回到全景 |
| `R` | 换个种子重铺地形 |
| `Esc` | 取消放置；没有在放置时才退出 |

也可以一开始就带着鱼启动：`cargo run --release -p vivarium-game -- --fish 40`。

**想看清细胞，把窗口开小一点再放大。** 512² 的世界塞进 1100 px 的窗口是 2.1 px/格，
一条三格鱼总共 6×2 像素——不是渲染坏了，是采样率不够。两个办法：

```bash
# 让世界变小，同样的窗口就有了 8.6 px/格
cargo run --release -p vivarium-game -- --width 128 --height 128 --fish 20
```

或者直接滚轮放大到十几倍。窗口标题里那个 `px/格` 就是当前密度。

`vivarium-sim` 不依赖任何图形库，可以在没有显示器的机器上跑长测。
它的报告里有四个比 hash 更该盯的数字：**活跃块数**（世界平静后应当掉到 0）、
**材质变化表**（守恒出问题时直接告诉你是哪种材质多了或少了）、
**工人数**（这一跑实际用到了几个线程），以及
**能量账的差额**（只要不是 0，就说明有一条能量通道没走记账点）。

## 打包

每完成一版都打一次包，产物是**双击就能跑的单文件 exe**（不需要装 Rust、不需要装任何运行库）：

```powershell
.\scripts\package.ps1              # → dist\vivarium.exe
.\scripts\package.ps1 -IncludeSim  # 顺带打包 headless 模拟器
```

`dist\VERSION.txt` 记录这一份是哪个 commit 构建的。`dist/` 不入库——
仓库里只有源码和这个脚本。

打包完记得**试运行一次**：编译通过不等于 exe 能跑，wgpu 的适配器初始化
只有在真的开一次窗口之后才知道成不成。

> 中文提交信息在 `VERSION.txt` 里会乱码，除非调 git 之前把
> `[Console]::OutputEncoding` 改成 UTF-8。PowerShell 解码外部程序 stdout 时用的是它，
> 而它在中文 Windows 上默认是 GBK(936)——git 吐出的 UTF-8 字节被按 GBK 解，
> 就成了"璁╃粏鑳炵湅寰楄"。不是 git 的问题，是宿主的问题。

### 想看一眼渲染结果

不用开窗口，直接把离屏渲染导成 PNG：

```bash
cargo test -p vivarium-render --lib -- --ignored --nocapture render_preview_png
# → target/render-preview.png          刚生成的地貌
# → target/render-preview-settled.png  材质层跑完之后的同一张图
# → target/render-preview-life.png     放鱼并跑 300 tick 之后

# 放大看细胞：一个近景、一个全景
cargo test -p vivarium-render --lib -- --ignored --nocapture render_preview_cells
# → target/render-cells-close.png      17 px/格，看得到膜、融合、按功能上色
# → target/render-cells-wide.png       zoom 3，看地貌与鱼群分布
```

像素渲染的 bug（颜色偏了、上下颠倒、留边错位）几乎都是"看一眼就知道、
但很难写好断言"的那一类。三张图能一次覆盖全部像素，而它们的**差异**
就是"材质规则和生命层真的在工作"最直观的证据。

第三张还钉住一件容易写错的事：细胞格的材质字段永远是 `Empty`，
如果脏块检测只看材质，鱼在水里游的时候渲染器会认为什么都没变，画面上一条鱼也没有。

近景那张另外钉住一条：**同一条鱼的细胞必须连成一块，不能有接缝**。
这条在 CPU 侧完全看不出来（键都写对了），只有真的把像素读回来量接缝亮度才发现——
第一版融合逻辑写对了，但明暗用了到格边界的距离，格边界处亮度归零，
身体于是又被切回一颗颗糖。

## 项目结构

```
crates/
  core/    模拟内核：材质、材质流动（含并行调度）、细胞与有机体、生命层调度、
           网格分块、确定性随机、地貌生成、手工体型（`body.rs`）、
           形态发生（`grn.rs`）  ← 零依赖
  render/  Renderer trait + ASCII 渲染器 + wgpu 像素渲染器
           （`shaders/blit.wgsl` 里做 SDF 细胞形状、融合、按功能上色）
  ui/      界面层：主题（`theme.rs`）、自绘控件（`widgets.rs`）、
           五个面板（`panels.rs`）、状态与命令（`state.rs`）
           ← **只有 egui，没有 wgpu / winit**
  app/     主循环、输入、时间控制
bins/
  sim/     headless 模拟器
  game/    图形前端（winit 事件循环 + egui 的 GPU 接线，见 `ui_glue.rs`）
```

地貌生成刻意放在 `core` 而不是各个 bin 里：M0 期间它被复制了三份
（sim / game / 渲染预览测试），三份已经开始漂移。世界形状是**设计决定的载体**，
不该有互相矛盾的实现。

## 四条架构约束

这几条不是风格偏好，是设计决定：

1. **`core` 不依赖任何渲染或窗口库。** 验证进化靠的是"跑几千上万代"，不是"盯着画面看"。
2. **`bins/sim` 刻意不依赖 wgpu / winit / egui。** 一旦它拉进图形依赖，每次编译多等几分钟，长跑调参就废了。
3. **`render` 不依赖 winit。** 它只接受一个已经建好的 `wgpu::Surface`——窗口是应用层的事，画像素不是。这样 headless 渲染不必拖进一整套窗口系统。
4. **`ui` 不依赖 wgpu / winit。** 只有 `egui`。界面的布局、配色、控件逻辑都能在**没有显卡**的机器上测——`crates/ui` 的两条测试正是这么跑的。把三角形提交给 GPU 是 `bins/game` 的事。

另外，`Renderer::render` 只接收 `&World`——"切换渲染器不改变模拟结果"这条验收断言，靠签名在编译期兜底。

## 渲染：脏块增量上传

世界纹理与世界同尺寸（512² 约 1 MiB），但**每帧只重传变过的 64×64 块**。

带宽其实不是瓶颈（1 MiB × 60 FPS = 60 MiB/s，GPU 不在乎）；
真正的成本是 CPU 侧的逐格转换——262144 个格子逐个算、逐字节写入。
分块之后，静止的块连这一步都省了。

这与 SPEC 第 2.4 节一致：落沙层的成本取决于**活跃格子比例**，不是网格大小。

按 `R` 重铺地形时，窗口标题里的"本帧上传"会瞬间跳到满格再掉回 0——
那就是增量逻辑在工作的直接证据。

## 纹理存的是语义，不是颜色

世界纹理是 `R32Uint`，每格一个键：

```
0x8000_0000 | (organism << 8) | cell_type
└─ 是细胞      └ 个体 id        └ 细胞类型
```

**颜色、形状、膜、轮廓光，全在 shader 里从键算出来。** 一开始的写法是 CPU 查调色板、
往纹理里写 RGBA——那意味着"这一格长什么样"在 CPU 侧就定死了，而 CPU 一格只能写一个颜色，
所以一格只能是一个方块。

想要圆角、想要同一条鱼的细胞连成一整块、想要膜在身体内部不出现、想要按功能而不是按个体上色，
这些全是**像素级**判断，只能在 shader 里做，而 shader 需要的是语义，不是颜色。

于是占格表多了一个 `kind: u8`（这一格是嘴还是生产者）——**不多占内存**，
`u32 + u16` 本来就要 padding 到 8 字节，白赚。之所以存在占格表而不是让渲染器去查生命层：
渲染器只拿得到 `&World`，为了知道"这是嘴"而让它持有整个 `LifeSim`，是把两层焊死。

### 融合不是"画粗一点"

同一条鱼的相邻细胞之间不该有缝。做法是**查四邻居**：同 `organism` 的一侧，把边界从格内
推到格外（`±0.5 → ±1.0`）。于是身体内部那几面墙根本不存在——边界是**从邻居关系推出来的**，
不是估出来的，所以身体形状换了会自动跟着变。

这里有一个只有把像素读回来才发现的坑：融合逻辑写对了，但明暗用了"到格边界的距离"，
而那个距离在格边界处正好归零。结果是**刚融合好的身体又被切回一颗颗糖**。
改成按"到格心的距离"算，融合处的亮度由两侧各自贡献，不会掉到零。

基础亮度也因此从 0.5 抬到 0.72：细胞边界处亮度本来就低，基础值再低，
两颗细胞相接的地方会暗到和水几乎同色，看起来像断成两截。

### 按功能上色，不按个体

嘴橙红、生产者绿、移动青蓝、眼黄、杀手紫红、装甲灰蓝、构造器琥珀。
这条是从 ALIEN 借的视觉语言：**看颜色就知道这格在干什么**。

按个体上色看起来更"丰富"，但它把注意力引到"这是谁"，而结构信息在"这是什么"。
一个身体要能看出结构，先得让同一种细胞在视觉上连成一片。

## 相机

`Viewport { center, zoom }`，属于渲染层，**不进世界哈希**——它改变的是"看哪里"，不是"发生了什么"。

滚轮缩放、方向键平移一成视口、`0` 回全景、`+`/`-` 快速缩放。窗口标题实时显示 `px/格`。

这个功能存在的理由只有一个：**512² 塞进 1100 px 的窗口是 2.1 px/格**，
一条三格鱼是 6×2 像素。在加相机之前，"看不到细胞结构"看起来像渲染 bug，
实际是采样率不够——`--width 128 --height 128` 一行就能零成本验证。

> 顺带一个调试陷阱：`ensure_world` 首次建纹理会把相机重置到世界中心。
> 离屏渲染测试里如果先设 viewport 再 `upload()`，重置会**静默覆盖**掉视口，
> 结果看起来像"细胞根本没画出来"——但键、shader、绑定全是对的。
> 修法是先 upload 再设 viewport，并且只在世界尺寸真的变了时才重置。

## 可复现性

所有随机走固定种子的 PCG 发生器（手写、零依赖），禁用系统随机。
契约：**同种子 + 同操作序列 ⇒ 同结果**，网格哈希逐 tick 一致。

```bash
cargo run -p vivarium-sim -- --quiet --seed 42 --ticks 1000 | grep hash
```

材质层每格每 tick 要做的随机决策（往哪边滑、这一格点不点得着）走的是
**位置派生**随机数 `Rng::at(x, y, tick, salt)`，而不是上面那个顺序推进的 RNG。
理由不是性能，是**可验证性**：共享的顺序 RNG 会让"哪些格子先被处理"变成世界状态的一部分，
于是并行化和跳块扫描都成了无法验证的赌博。

换成位置派生之后，"跳块扫描"与"每 tick 全网格扫描"给出**逐格相同**的结果，
这条性质是直接写成测试的（`skipping_static_chunks_matches_a_full_scan`）。
并行也是同一回事：`--threads 1` 与 `--threads 16` 逐 tick 哈希相同
（`thread_count_does_not_change_the_world`）。

但**扫描顺序本身**是这个世界定义的一部分。分块按棋盘相位分组是并行的前提，
而分组必然改变"谁先被处理"——把顺序改掉，同一个种子会长出另一个世界
（物理结果不变，具体排布会变）。所以有一条黄金哈希测试
（`the_scan_order_is_part_of_the_world`）钉住它：以后谁动扫描顺序，它会立刻红。

| 512² × 20,000 tick（真实地貌，绝大部分时间静止） | **146 ms**（0.0073 ms/tick） |
| 世界静止所需 | **221 tick**（此后活跃块恒为 0，每 tick 访问 0 格） |
| 测试 | 136 个全绿 · clippy 零警告 |
| 跳块 vs 全扫 | 400 tick 逐 tick 逐格哈希相同 |
| 线程数 vs 结果 | 1 / 2 / 4 / 8 / 16 线程，逐 tick 哈希相同 |

**多线程已经接上了**，而且不是"能跑就算"：分块先拷进私有副本、规则只在副本上跑、
相位之间由主线程顺序写回，所以线程之间没有任何共享的可变状态——
"线程数不影响结果"是构造上成立的，不是靠多跑几次碰运气。

调参用 `--threads N`，默认 0 = 自动（按本机核数与当 tick 活量收敛）。
注意**不是线程越多越快**：建一个线程约 30 µs，所以 `--threads 16` 在这台机器上
反而比 8 慢——自动档就是为了避开这件事。

**加大体型不是换个数据表。** 它把一整类只在多格身体上才显形的问题一次全暴露了，
五个真 bug 里有三个是同一件事的不同面孔——**生物会离开水**：

1. **感知探针取在锚点上。** `front()` 返回锚点右侧一格，而三格鱼的身体本来就占住
   那一格——"前方被挡"恒为真，手工鱼其实**一直在往左游**。它看起来正常，只因为
   撞到左墙会反向。十几格的身体把这个错放大到无法忽视。
2. **繁殖是爬进天空的梯子。** 子代位置在亲代 6 格以内，而 `can_place` 对空气放行。
   水面上的鱼可以一路往上生，每代 6 格。
3. **被挤上去的水成了下一代的落脚点。** 见上面「借水」那节。
4. **尸体腐烂成"空"，水回不来。** 海底攒出空气腔，水位被永久顶高。
5. **干残骸永远不烂（吸收态）。** 概率给 0 就是只进不出，天空里那层尸体永不消失。

还有一个不是模拟的：**`cargo test` 并行跑 GPU 测试会 `STATUS_ACCESS_VIOLATION`**。
DX12 的软件适配器上多个 device 并发创建不是线程安全的，现象是"跑三遍崩两遍、
单线程跑全绿、而且不告诉你崩在哪个测试里"。加一把全局互斥锁把 GPU 测试串起来即可。

### 一次失败的实验：把生态推到"觅食受限"

目标：24 的时候光本身就够活，"跑得快 / 看得远"永远不如"多长一个生产者"。
要让形状有东西可优化，得让光**不够**活。做法是 `PRODUCER_YIELD` 24 → 15 +
藻生长率 8% → 40%。**失败了，已回退。** 三个硬障碍：

1. **食物在海底不可达**：48 条鱼 4000 tick 全灭，藻席堆到 800 格没人吃。
   海深 184 格，一趟往返移动成本 ≈ 4800，而一格藻只有 120 能量。
2. **加"饿了往下"也不够**：下潜要 184 tick，启动能量只够撑 125 tick。
3. **改成浮游藻把世界冻住**：藻是静态固体，悬在水里就成了水流的障碍——
   1500 格时 `活跃块` 掉到 3/64，3000 格时整个世界静止（`移动 0`）。

**这不是调参能解决的。** 要让食物"可达又不成障碍"，藻需要自己的移动规则
（随水漂、可被水挤开），那是一次材质层的改动。在那之前宁可"光照受限"但生态健康。

> 一句话：**"食物在哪"和"食物是什么"是同一个问题。** 把食物放在鱼到不了的地方，
> 等于没有食物；把食物做成挡路的东西，等于把海填了。

| 藻 | 700 格材质 | **150 个单细胞生物** |
| 细胞 | 450 | **830** |
| 深度范围 | 153–188 | **154–220** |
| 飘在天上 | 0 | **0** |
| 能量账差额 | 0 | 0 |

**四个坑，每一个都表现为"生态突然全灭"：**

1. **上限检查读的是上一 tick 的统计。** `stats` 在 `step` 开头刚被重置，
   读它永远是 0——藻涨到 1156 个（上限 600），把光吃光，鱼饿死绝种。
2. **嗅觉不认识藻。** 射线只找含能量的材质，藻变成生物之后看不见了。
   鱼闻不到食物、藻又占格不让进 → 500 tick 全灭。
3. **吃藻会让索引错位。** `act` 按索引遍历，当场 `remove` 会让后面的
   索引全部错位。改成延迟删除。
4. **吃藻会漏水。** 藻借走的那格水没还——600 tick 少了 1919 格。

另外两个"一放进去就失控"的：**海草自动投放会涨到 481 株**（固着生物
不付移动成本，天然占优）；**藻上限 300 会抢光**（容纳量 2400 时鱼才活得下去）。

**五个 bug，全都是"看着能跑、其实不对"：**

1. `touches_water` 把气体和藻算成水 → 鱼贴着水面那行藻就能浮到水面之上。
2. 判据看"表面有多少水"时，**窄鱼的侧面几乎总是水**——3 列宽的鱼哪怕头顶
   出水 4 格，占比照样过半。
3. `try_move` 把旧位置也算进身体 → 旧位置（在水里）盖住新位置（在空中），
   鱼可以一格一格往上爬。
4. `OUT_DOWN` 根本没有驱动 → 垂直方向永远是"负或零"，鱼只有两个方向可选。
5. `clamp(-8, 8)` 把趋光增益 12 截断成 8 → `OUT_DOWN` 从 `+1.6` 变成 `-1.2`，
   鱼不但不下潜还主动上浮。**表里写 12、跑起来是 8。**

另外两个"改了一半又退回去"的实验：

- **藻密度改成和水一样（4）**，想让藻悬在撒下的那一层。结果 700 格藻成了
  水流里的半固体障碍：1000 tick 后 `活跃块 4/64`、`移动 18`，世界冻住、鱼全饿死。
  **悬浮物要么被水推着走，要么挡水，没有中间状态。**
- **趋光设定点设成 0.60**（走廊在水面下 63~81 格），垂直占比 86%，
  但**种群从 60 塌到 5**。生产者收益与光成正比，深处养不活种群。
